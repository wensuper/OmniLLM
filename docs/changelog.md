# 更新记录

## v0.2.0-alpha.23（2026-10-21）

安装和更新重新设计，目标是装一次就不用再管：

- 安装命令变成一行 `curl -fsSL …/install.sh | sh`，不再留下安装脚本文件；下载到一半断了不会执行半截脚本。
- 主机会自己更新：启动几分钟后、之后每 6 小时看一次新版本，等 10 分钟没人用的时候装上，重启几秒，设备自己重新连上。不想要可以 `omnillm update --auto off`。
- 新命令 `omnillm update`（主机和只当设备用的服务器都能用）和 `omnillm update --check`。`omnillm status` 会说有没有新版本。
- 新版本启动不起来时，自动换回原来的版本，以后也不再自动装这一版。
- 在只当设备用的服务器上再运行一次安装命令，按设备更新，不会把它变成主机。
- 再安装一次（包括更新）会保留自己部署的连接服务和网页地址；以前从终端重装会丢掉。
- 服务器上的 `omnillm connect` 在有新版本时提一句。
- README 精简成 Quick Start；“能用哪些模型”移进快速上手，“和别的做法比”移进安全说明。
- 手机网页还没配对时的首页重新设计：网格和极光背景、主机和设备的轨道示意、三步说明、渐变标题；没有主机的人可以直接点到安装说明。

Mac 菜单栏的菜单重新排过，和 NEXA 一样：

- 最上面一行说清现在的状态（如“在线 · 手机和其他设备能连上”），下面是“设备  2 台在线 / 共 3 台”“模型来源  3”，点一下直接打开控制台对应的页；再下面是添加设备、打开控制台；最后是版本和“检查更新…”。不再是三行灰字。
- “检查更新…”点了菜单不收起，结果就显示在那一行；有新版本时点“有新版本 X · 点击更新”，和主机自动更新走同一条路。
- 菜单栏图标一直在，菜单里不再有“从菜单栏移除”；菜单文字跟随系统语言。

订阅对话接着上一轮的会话说：

- 用 Claude 或 ChatGPT 订阅聊天时，后面的每一句不再把整段对话重发一遍：主机接着 Claude Code / Codex 上一轮的会话说，回答更快，长对话也更省订阅额度。改了前面的话、重新生成或换了模型时，自动从头来。
- 这段对话会留在主机上（Claude Code / Codex 自己的会话文件里），一天没用、设备被移除或订阅被移除时删掉。

六轮产品评审（新手、日常使用、视觉对照 NEXA、出错与边界、中英文案五个视角，每轮全量截图）后的改动：

- 用词统一：你的 Mac、远程连接、模型来源、每天额度、API Key；控制台按主机系统说“这台 Mac”或“这台电脑”；命令行按终端的语言回答。
- 设备和应用：编辑弹窗（名字、开启或暂停、每天额度或不设上限、能用的模型、移除），暂停开关，是否在线，今天花了多少；整台 Mac 的每天总额度可改；重名自动编号“iPhone (2)”，手机上显示 Mac 给的名字。
- 模型：名字带版本（后台每周最多问 3 次，没用过也知道），可改名、可不在设备上显示，订阅被移除后不会自己回来，“重新检查”能把订阅接回来；模型来源显示登录失效、到上限及恢复时间。
- 用量：按名字显示，今天 / 昨天 / 最近 7 天，按模型分，合计。
- 手机：添加和核对数字的页面重写，“重新回答”保留之前的回答，真正的列表，回答流式时不闪半截格式，搜索对话，暂停、断线、正在连接的提示，同一手机两个标签页互相让，移除这台设备时 Mac 上也一并移除，网页自己更新。
- 控制台：中文输入法选字的回车不会误点（以前会直接批准设备），浏览器自带的确认框全部换成页面里的，窄屏表格不再折字，NEXA 的开关、分段按钮和提示样式。
- 命令行：`hub device set` / `app set` / `model set` / `provider rm` / `daily-total`，表格代替原始 JSON（`--json` 仍可用），名字有歧义时拒绝并列出 ID，选项写错先说哪里错，`omnillm status` 列出需要处理的模型来源；中文不再出现被截断的乱码。
- 报错：等待时间按读者语言（“约 3 小时”），每句都说下一步怎么做。

## v0.2.0-alpha.18（2026-10-21）

alpha.17 上线后全面测试发现的问题：

- 发图片时网络断了几秒（例如手机切换 Wi-Fi 和流量），恢复后显示“内部出错”。原因是网络恢复时页面重新打开了连接，把正在路上的请求关掉了。现在不再重开；回答还一个字没到时断线，会自动再问一次。
- 两台同名设备（都叫 “iPhone”）在控制台里分不清，删的时候可能删错。新配对的重名设备会自动编号，例如 “iPhone 2”。
- 主机刚启动的几秒里打开控制台“添加设备”，会一直说“还没有配置连接服务”，而且不会自己恢复。现在显示“正在连上连接服务”，连上后自动出二维码；状态行也会自己更新。
- `omnillm status` 在连接服务连不上时也说“一切正常”。现在会说明连接服务暂时连不上、手机暂时用不了。
- 中文环境下安装脚本最后报 “tag: unbound variable”（变量后面紧跟中文标点被当成变量名的一部分）。

## v0.2.0-alpha.17（2026-10-21）

- 有的浏览器不允许把“不可导出”的密钥存进本地存储（会报英文的 “The object can not be cloned.”），配对后就卡在配对页。现在这种浏览器也能配对和使用，密钥只在页面打开期间有效（仍然不可导出），页面用一句话说明“关掉后要在主机上重新添加，换用 Safari 或 Chrome 可以一直保存”。Safari、iPhone 上的 Chrome 不受影响。

## v0.2.0-alpha.3（2026-10-20）

第三轮安全审查和公网测试后的修复：

- 图片：除了格式和大小，还按图片头里的尺寸拦下“几 KB 却声称几十亿像素”的图片（单边 ≤ 8192，总共 ≤ 约 4000 万像素），免得主机上的 Claude Code / Codex 解码时吃光内存。
- 长对话里图片多了也不会卡住：只有最近两条带图的消息附图片，更早的图片在文字里注明。
- 网页客户端：页面、脚本和 Service Worker 带同一个构建号；服务器切换版本时恰好打开、拿到新旧混合的页面，会自动清缓存重新载入一次，不会把混合版本缓存下来。
- 服务器部署：连接服务用自己的无登录账号运行（systemd 加固），网页文件归 root、只读，连接服务被攻破也改不了手机加载的网页；打包没有 cosign 就停下；服务器上安装前再核对一遍签名的校验和；网页目录不跟随符号链接；如果有日志格式会记录浏览器信箱口令所在的请求头，安装就停下。
- 手机断网时马上提示“这台设备没有联网”，刚输入的内容留着，联网后自动重新连上；连上主机前就点了发送的消息，会等模型列表加载好再发出（公网上列表比聊天界面晚到一点）。
- 连接服务对 IPv6 按 /64 计猜口令次数。
- Codex 附图片改成单个参数，不会把读提示词的 `-` 当成图片。
