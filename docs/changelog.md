# 更新记录

## v0.2.0-alpha.4（2026-10-20）

包含 alpha.3 的全部修复，另外：

- 配对二维码更容易扫：配对文字改成紧凑格式（`omnillm2-`，长度约减半），二维码点更大、更稀；旧格式 `omnillm1-` 仍然能用。网页客户端要先于中心节点升级（发版顺序：服务器网页 → 各人的中心节点）。
- 控制台“添加设备”：二维码放大，手机只看一句话；电脑或服务器的步骤收进“电脑或服务器（没有摄像头）”，里面有一行安装命令（只装程序、不装服务，装完提示粘贴配对文字）和配对文字，各带复制按钮；确认时的 6 位数字按“123 456”显示，和手机上一样。
- 日志脱敏明确覆盖两种配对文字和配对链接。

## v0.2.0-alpha.3（2026-10-20）

第三轮安全审查和公网测试后的修复：

- 图片：除了格式和大小，还按图片头里的尺寸拦下“几 KB 却声称几十亿像素”的图片（单边 ≤ 8192，总共 ≤ 约 4000 万像素），免得主机上的 Claude Code / Codex 解码时吃光内存。
- 长对话里图片多了也不会卡住：只有最近两条带图的消息附图片，更早的图片在文字里注明。
- 网页客户端：页面、脚本和 Service Worker 带同一个构建号；服务器切换版本时恰好打开、拿到新旧混合的页面，会自动清缓存重新载入一次，不会把混合版本缓存下来。
- 服务器部署：连接服务用自己的无登录账号运行（systemd 加固），网页文件归 root、只读，连接服务被攻破也改不了手机加载的网页；打包没有 cosign 就停下；服务器上安装前再核对一遍签名的校验和；网页目录不跟随符号链接；如果有日志格式会记录浏览器信箱口令所在的请求头，安装就停下。
- 手机断网时马上提示“这台设备没有联网”，刚输入的内容留着，联网后自动重新连上；连上主机前就点了发送的消息，会等模型列表加载好再发出（公网上列表比聊天界面晚到一点）。
- 连接服务对 IPv6 按 /64 计猜口令次数。
- Codex 附图片改成单个参数，不会把读提示词的 `-` 当成图片。

## v0.2.0-alpha.2（2026-10-20）

- 文字 + 图片：手机和平板上点图片按钮（相机或相册）或直接粘贴，图片在手机上先缩小再发；终端里 `omnillm connect ask --image 文件`、对话里 `/image 文件`；本机接口接受 OpenAI / Anthropic 格式的内联图片（不替程序去下载网址）。订阅也能看图：Claude Code 走它的 JSON 输入，Codex 用 `-i` 读私有临时目录里的图片文件，工具仍然全部关闭。每张图不超过 2 MB、每条消息最多 4 张，中心节点按文件内容核对格式。看不了图的模型会直接说明。
- 界面：模型名里的“订阅”跟着界面语言显示；图片和发送按钮换成清楚的图标；离线提示里的“重试”不再折行；回复里段落前后不再多空行。
- 修复：在主机上移除设备后，手机约 1 秒就知道并回到配对页（以前要 8 秒）；订阅的请求节奏允许连发 4 条，每分钟 12 条。
- 网页客户端启用压缩（7.5 MB → 约 2 MB），手机第一次配对从约 31 秒降到约 11 秒；网页客户端的 manifest 类型改对（服务器配置，见 deploy/）。
- 主机日志记录每次调用等了多久（第一个字和总时间），不记内容。
- 修复：升级时后台服务偶尔没重新注册上（launchd 还没卸完就注册），现在等它卸完并重试。

## v0.2.0-alpha.1（2026-10-19）

Mac 上登录好的 Claude 或 ChatGPT 订阅，手机、平板、Linux 服务器都能用；除了 Mac，别处尽量不装东西。

- 订阅：中心节点直接用已登录的 Claude Code 和 Codex（官方程序），当纯文本模型跑：不开工具、不读主人的设置和说明文件、不留会话；Codex 在中心节点自己的目录里跑，只链接主人的登录文件。装好、启动、`omnillm status` 或打开控制台时自动接上。
- 防封号：订阅只给人用（代码里写死，主人也关不掉）；一次一个、每分钟 12 次、每台设备每小时 60 次；订阅用量到顶就按官方给的恢复时间暂停；每个新版本的官方程序先过“能不能用工具”的检查，过不了就不用。
- 手机和平板：扫控制台上的二维码直接打开网页客户端（不装 App），在网页里配对和对话；加密在网页里用和命令行同一份代码（WebAssembly）完成，配对状态和对话加密存在浏览器里。
- Linux 服务器：`install.sh --device` 只放一个程序、不装服务，粘贴配对文字就能用；`omnillm connect chat` 在终端里多轮对话；脚本（没有终端）用不了订阅。
- 被移除的设备会被明确告知“已被移除”，不再一直显示“连不上主机”。
- 公共连接服务 `wss://relay.ixxzh.com` 和网页客户端 `https://omni.ixxzh.com`（放在 ixxzh.com 的服务器上，步骤见 docs/relay-deploy.md）：中心节点默认连它；网页客户端随发布签名，不再用 GitHub Pages。
- 请求节奏：订阅额度暂时用完时，20 秒内能轮到的就等一下再发，不再报错。

## v0.1.0-alpha.2（2026-10-18）

两台机器（Linux 服务器做中心节点、Mac 做中心节点）各跑多轮完整流程后修的问题：

- 半途放弃的配对不再占名额：命令行退出、控制台重开“添加设备”或关掉页面、SDK 的 ctx 结束，配对都立即作废。以前 8 次放弃之后 5 分钟内配不了新设备。
- relay 刚重启时发起配对会等它重连（最多 15 秒），设备连信箱最多重试 20 秒；连不上 relay 时提示“连不上”，不再误报“配对文字过期”。
- relay 断开后中心节点几秒内重连（间隔封顶 10 秒）；连上又马上断的才继续拉长间隔。
- 控制台默认端口被别的程序占用时换下一个空闲端口，登录链接跟着走；只有嵌入模型的 Ollama 不自动接入；没有屏幕的机器提示在终端里输入密钥；Linux 服务也写 hub.log；设备本机接口令牌错误时提示清楚；发布附带 Sigstore bundle。
