# 更新记录

## v0.1.0-alpha.2（2026-10-18）

两台机器（Linux 服务器做中心节点、Mac 做中心节点）各跑多轮完整流程后修的问题：

- 半途放弃的配对不再占名额：命令行退出、控制台重开“添加设备”或关掉页面、SDK 的 ctx 结束，配对都立即作废。以前 8 次放弃之后 5 分钟内配不了新设备。
- relay 刚重启时发起配对会等它重连（最多 15 秒），设备连信箱最多重试 20 秒；连不上 relay 时提示“连不上”，不再误报“配对文字过期”。
- relay 断开后中心节点几秒内重连（间隔封顶 10 秒）；连上又马上断的才继续拉长间隔。
- 控制台默认端口被别的程序占用时换下一个空闲端口，登录链接跟着走；只有嵌入模型的 Ollama 不自动接入；没有屏幕的机器提示在终端里输入密钥；Linux 服务也写 hub.log；设备本机接口令牌错误时提示清楚；发布附带 Sigstore bundle。

## v0.1.0-dev（2026-10-18）

- 库：`hub`（主机）、`device`（设备）、`relay`（连接服务）、`localapi`（本机 OpenAI 兼容接口）。
- 端到端加密（Noise IK / IKpsk2），连接服务看不到内容。
- 唯一上游出口：限流、退避、熔断、人优先；预算按最坏情况预留。
- 配对：配对文字 + 主机上确认 6 位校验码，配对后更换信箱口令。
- 命令行 `omnillm`：主机、设备、连接服务。
- 测试：单元、模糊、竞态、端到端（抓取连接服务流量）、对抗、两轮独立审查的回归、静态分析、真实程序冒烟。
- 本机控制台和首次运行向导；二维码配对；`omnillm install / uninstall / status / open`；写给 AI 的 INSTALL.md 和校验下载的 install.sh；GoReleaser 签名发布和 CI。
