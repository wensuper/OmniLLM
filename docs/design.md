# OmniLLM 概要设计

> 状态：v0.7（2026-10-22）。v0.7 按 v0.2.0-alpha.39 的代码校对了现行行为（安装与自动更新、菜单栏、订阅引导登录、控制台、网页对话、发布流程）。之前：v0.6 写入了 v0.1 代码的实现状态（§13）；v0.2 按原则 1、2 重做了网络结构；v0.3 架构评审修正（§11）；v0.4 产品评审修正（§10、§12）；v0.5 改为库优先，以 SDK 融入 NEXA、不另装软件（§2.4、§8）。
> 一句话：**一处接入大模型，所有设备都能用。** OmniLLM 是一个个人工具，不是平台。
> 本文服从 [principles.md](principles.md)。两者冲突时以原则为准。

## 1. 定位与范围

**是什么**：一个 Go 库（SDK），加上用它做成的单文件程序。库可以嵌进别的程序（首先是 NEXA），程序给没有 NEXA 的人单独用。装在“中心节点”（Mac、PC 或服务器）上时，它是**唯一**和大模型打交道的地方，保管所有凭据；其他设备（手机、平板、别的电脑或服务器）配对后，经过中转服务器、以端到端加密的方式请中心节点代为调用模型。

**解决的问题**：

- 每台设备都要配一遍 API Key 或登录一遍，凭据散落各处，丢一台设备就得全部换掉。
- 多台设备、多个 IP 同时用一个账号，容易被提供商判定为账号共享而封号。
- 本地模型（Ollama 等）只能在本机用，手机、平板用不上。

**设计原则**（详见 [principles.md](principles.md)）：

1. **只有中心节点和大模型交互，账号不能被封**。
2. **中心节点和设备之间只经过服务器中转，端到端非对称加密，服务器看不到内容**。
3. 凭据（API Key 和登录会话）不出中心节点。
4. 默认安全。
5. 规则写在代码里。
6. 够用就好：一个主人，多台自己的设备。
7. **以代码（SDK）融入 NEXA，不另外安装软件**：OmniLLM 首先是 Go 库，NEXA 直接引入，当它的大模型和 AI 应用（§2.4、§8）。
8. **不懂技术的人也能 5 分钟用上**：不需要自己的服务器，向导三步走完（§10）。

**谁能用**：有至少一个官方 API Key（OpenAI、Anthropic、Gemini 等），或者在中心节点上装了本地模型（如 Ollama），或者有 Claude / ChatGPT 付费订阅。订阅不碰网页登录：中心节点运行主人在本机登录好的官方命令行程序（Claude Code、Codex），只给人手动对话用（§13.3）；没装或没登录的，控制台和 `omnillm login` 引导一步装好、登录（§10.8）。

**不做（v1）**：多用户或团队计费；把账号分享给别人用；导出或转发网页版订阅的登录态；局域网直连或点对点组网。

## 2. 总体架构

```
                         模型提供商（OpenAI / Anthropic / Gemini …）、本地模型
                                        ▲
                                        │  唯一的上游出口（限流 · 退避 · 熔断）
 ┌──────────────────── 中心节点 omnillm hub（不开放任何对外端口）─────────────────┐
 │  E2E 会话层   Noise IK：校验设备公钥 → 解密请求 / 加密响应                       │
 │  鉴权层       设备公钥白名单 → 可用模型、额度、到期                              │
 │  路由层       统一请求格式 → 选择 Provider → 流式结果                           │
 │  Provider 出口 OpenAI · Anthropic · Gemini · OpenAI 兼容 · Ollama               │
 │  凭据库       API Key 和登录会话，系统钥匙串或加密文件                       │
 │  控制台       仅限本机 127.0.0.1，凭本机登录用户身份：配对、吊销、额度、审计       │
 │  存储         键值存储：设备公钥、额度、审计（不存对话内容；订阅续接见 §13.4）      │
 └───────────────────────────────┬──────────────────────────────────────────────┘
                                 │ 主动外连 wss://（TLS）
                                 ▼   帧内容：端到端密文
                    ┌──────── 中转服务器 omnillm relay ────────┐
                    │  按随机信箱编号转发字节；不落盘、不记内容  │
                    │  看不到：内容、模型、用量、设备名、凭据     │
                    └──────────▲──────────────▲──────────▲──────┘
                               │ 主动外连 wss://           │
                         手机 / 平板        其他电脑        服务器 / 脚本
                        （网页客户端 /    （omnillm connect：  （omnillm connect：
                          原生 App）        本机 OpenAI 接口）    本机 OpenAI 接口）
```

设备和中心节点都只做**主动外连**，彼此之间没有任何直连路径。中心节点不监听对外端口，只开本机管理端口。

### 2.1 组件

| 组件 | 说明 |
|---|---|
| OmniLLM 库（SDK） | 全部能力的实现，嵌入 NEXA 等宿主时直接引入（§2.4） |
| `omnillm hub` | 独立程序的主机模式：库的 `hub` 包外加控制台、CLI |
| `omnillm relay` | 中转服务器，同一个程序的另一种模式；按设计**不可信**，谁部署都一样 |
| `omnillm connect` | 设备端代理：在设备本机开一个 `127.0.0.1` 的 OpenAI 兼容接口，把请求加密后经 relay 发给中心节点。现有 App 和 SDK 把 `base_url` 指向它即可 |
| 网页客户端 | 手机、平板用的聊天页面，从独立的静态地址发布（不由 relay 下发，见 §5.3） |
| 本机控制台 | 中心节点上的网页控制台（`omnillm open` 打开），首次运行向导、配对、设备、额度、用量都在这里；只在本机，靠本机登录用户的身份进入，不另设密码 |
| `omnillm` CLI | 和控制台功能相同的命令行（`install`、`status`、`open [--add]`、`update`、`login`、`hub pair / devices / revoke / app / provider / model / daily-total`；`backup` 排在 v0.3），也可在终端里对话 |
| 菜单栏（macOS） | `omnillm tray`：登录项，显示能不能连上、设备和模型来源的计数、添加设备、打开控制台、版本和更新、语言（§13.3） |
| 本机应用接口 | 中心节点和 `omnillm connect` 都只在 `127.0.0.1` 开 OpenAI 兼容接口，给同一台机器上不能嵌入库的第三方程序用；每个程序一枚应用令牌。中心节点默认开在 `127.0.0.1:8765`（§10.9）。NEXA 以库嵌入，不走这里 |

### 2.2 部署方式

| | 个人电脑做中心 | 服务器做中心 |
|---|---|---|
| 中心节点 | Mac / PC 上的 `omnillm hub` | VPS 或 NAS 上的 `omnillm hub` |
| 中转服务器 | **默认用项目提供的公共 relay，什么都不用装**；想自己掌握元数据，可以在自己的服务器上跑 `omnillm relay` | 同左；自己部署时可以和中心节点在同一台机器上，但中心节点仍只经 relay 和设备通信 |
| 凭据存放 | 系统钥匙串 | 加密文件，主密钥来自环境变量、systemd credential 或 KMS |
| 上游出口 | 这台电脑的网络 | 这台服务器的网络 |

### 2.3 一次请求的流程

1. 设备上的 App 调用本机 `omnillm connect` 的 `POST /v1/chat/completions`（或在网页客户端里发消息）。
2. 设备用和中心节点之间的 Noise 会话密钥加密请求，填充到固定长度档位，发到 relay 上自己的信箱。
3. relay 把密文原样转给在线的中心节点。它解不开，也不记录。
4. 中心节点解密，用设备公钥确认是哪台设备，检查是否被吊销、能否用这个模型、额度还剩多少。
5. 请求进入 Provider 出口：排队、限并发、限速；取出凭据发给提供商；遇到 429 按要求退避。
6. 结果按块加密、填充，经 relay 流式返回；为了省流量，流式内容每约 100 毫秒合并成一块再发，也顺带减少从节奏推测长度。设备端解密后交给 App。
7. 中心节点累计 token 用量，写一条审计（时间、设备、模型、token 数，不含内容）。

### 2.4 库优先：一套代码，两种用法

```
            ┌──────────────── OmniLLM 库（Go 模块 github.com/wensuper/OmniLLM）────────────────┐
            │  hub      主机：Provider 出口、凭据、设备、额度、审计、配对、工具转接                    │
            │  device   设备：连到主机、调模型、执行宿主登记的工具                                   │
            │  relay    连接服务（单独部署用）                                                     │
            │  宿主接口  SecretStore · Store · Transport · Logger · Locale · UI（确认、通知） · ToolHost │
            └───────────────┬──────────────────────────────────────────┬─────────────────────────┘
                            │ 嵌入                                       │ 包一层
                    NEXA（pgclient）                           omnillm 独立程序
              钥匙串、存储、出站出口、界面都用 NEXA 的        控制台、CLI、connect，用库自带的默认实现
```

**公开接口（草案）**

| 包 | 主要接口 | 说明 |
|---|---|---|
| `hub` | `New(Options) (*Hub, error)`、`Start(ctx)`、`Stop(ctx)` | 宿主决定何时启停；`Stop` 后不留任何 goroutine |
| | `Complete(ctx, Request) (Stream, error)` | 进程内调模型；`Request` 必须标明调用方是人（`Interactive`）还是后台程序（`Background`），后台只能走 API Key 和本地模型 |
| | `Models(ctx) []Model` | 每个模型带 `Locality`（`Local` / `Remote`）、提供方、显示名 |
| | `Pair(ctx, PairOptions) (*Pairing, error)` | 返回二维码内容、配对文字；`Pairing.Code()` 给出 6 位校验码，`Confirm()` / `Cancel()` 由宿主界面调用 |
| | `Devices`、`Revoke`、`Usage`、`SetBudget`、`AddCredential`、`RemoveCredential`、`Backup`、`Restore` | 凭据只能写入、删除和列出（末 4 位），没有读出明文的方法 |
| `device` | `Dial(ctx, Options) (*Device, error)`、`Complete`、`Models` | 主机在别处时，宿主嵌入设备角色 |
| | `RegisterTools(ToolHost)` | 宿主登记可以被远程调用的工具（§8.3） |
| `relay` | `NewServer(Options)` | 只给自己部署连接服务的人用 |

**宿主传入的接口**

| 接口 | NEXA 传入 | 独立程序的默认实现 |
|---|---|---|
| `SecretStore` | NEXA 的钥匙串封装 | 系统钥匙串或加密文件 |
| `Store` | NEXA 自己数据库里的一张表（或一个单独文件），库只用自己的键，不碰 NEXA 的数据 | 自己数据目录下的 JSON 文件（0600） |
| `Transport`（`http.RoundTripper` 和 WebSocket 拨号） | NEXA 的出站出口 `internal/egress` | 标准库 |
| `Logger` | NEXA 的日志（库已脱敏后再交出） | 标准错误输出 |
| `Locale` | NEXA 当前界面语言 | 系统语言 |
| `UI` | NEXA 的确认框和通知 | 控制台 / 系统通知 |
| `ToolHost` | NEXA 的 MCP 工具分发（§8.3） | 无 |

**错误**：库返回带类型的错误，和本机接口的状态码一一对应：`ErrBusy`（带 `RetryAfter`）、`ErrHubOffline`、`ErrInvalidToken`、`ErrModelNotAllowed`、`ErrUnsupportedFormat`。每个错误带一句给人看的话（按 `Locale`）。

**本机 HTTP 接口和应用令牌**只给不能嵌入库的第三方程序（各种 App、脚本、别的语言写的程序）用；NEXA 不需要它们。

## 3. 密钥、配对与设备管理

### 3.1 密钥

- 中心节点和每台设备各有一对长期的 X25519 公私钥。私钥只在本机：中心节点存进钥匙串；`omnillm connect` 存进设备的系统钥匙串；网页客户端用不可导出的 WebCrypto 密钥存进 IndexedDB。
- 每次会话按 Noise IK 模式握手：设备事先知道中心节点公钥，中心节点检查设备公钥在白名单里；会话密钥由临时密钥协商，具备前向保密。会话按时间和消息数定期重新协商密钥。
- **不做 0-RTT**：Noise IK 的第一条消息可以被录下来重放，所以它只用来握手，不带任何业务数据；握手完成后才收发请求。
- **协议版本**：握手负载里带协议版本和能力列表；协议只增不改，新能力双方都声明了才用，老设备照常能连。
- **换钥**：`omnillm rekey` 生成新的中心节点密钥对，经现有加密会话把新公钥发给每台设备，由旧密钥签名，设备核对后换上；旧私钥疑似泄露时不走这条路，直接全部重新配对。

### 3.2 配对（公钥只能当面交换）

1. 主人在控制台点“添加设备”（也可以 `omnillm open --add`、菜单栏「添加设备…」，或终端里 `omnillm hub pair`）。可用模型和额度已经预填（全部已接入的模型、每天 5 美元），不改也能直接下一步。
2. 中心节点在**本机屏幕**上显示二维码，内容是：relay 地址、这台设备专用的随机信箱编号和信箱口令、中心节点公钥、一次性配对密钥（256 位随机数，5 分钟过期，只能用一次）。**二维码不经过 relay 传送。**
3. 设备扫码，生成自己的密钥对，连到 relay 上的信箱，用 Noise IKpsk2 握手：配对密钥作为预共享密钥，证明这台设备确实扫过屏幕上的码。
   - **另一台电脑**：控制台「添加设备」上面一个切换，「手机或平板」｜「电脑或服务器」，一次只看一条路。电脑那条路给的是二维码里的同一个链接（「复制链接」），在那台电脑的浏览器里打开，后面和手机一样。链接由主人自己带过去，不经过 relay。
   - **没有浏览器的服务器**：「电脑或服务器」最下面一行「那台电脑没有浏览器？用命令行」，默认收起，点开是一条安装命令（`install.sh --device`，已经装过也运行这条，没配对过就直接问配对文字）和配对文字，各带复制按钮。安装命令中间省略、两头留着，看得到结尾的 `--device`。终端里粘贴配对文字是隐藏输入，页面上说一句“看不到字是正常的”。
   - **面板的样子**：左边一块原地变（二维码 / 复制链接 → 6 位数），过期或没添加成时就在那块上变灰，中间一个“换一个二维码”（链接、配对文字同理）；第 3 步在中心节点上点「一致，添加」；倒计时圈显示还剩多久。右边三步，当前那步高亮、做完的打勾，下面一行实时状态。中心节点不知道手机扫没扫码，所以没有“已扫码”这一步，等到设备请求加入才变到第 3 步（原则 44：对方的信号只在真发生时才显示）。
   - **中心节点是没有屏幕的服务器**：二维码和配对文字显示在主人的 SSH 终端里，确认也在终端里完成。
4. **主人在中心节点上确认**：握手完成后，中心节点和设备屏幕上都显示同一个 6 位校验码（由握手结果算出）和设备名，主人核对一致后在中心节点上点确认。只偷拍到二维码的人配不上，因为确认要在中心节点前完成。
5. 中心节点记下设备公钥和权限，作废配对密钥。relay 全程只看到密文。

配对的寿命跟着发起它的地方走：`omnillm hub pair` 中途退出（Ctrl-C、终端关掉），这次配对立即作废；控制台里再点一次“添加设备”会结束上一次，页面关掉 90 秒后也作废；SDK 里 `Pairing.Wait(ctx)` 的 ctx 结束、或调用 `Pairing.Cancel()` 同样作废。这样半途放弃的配对不会占着名额（同时最多 8 个）。中心节点刚和 relay 重连时，发起配对最多等 15 秒；设备连信箱最多重试 20 秒，连不上 relay 时说“连不上”，不说“配对文字过期”。

### 3.3 设备管理

- 每台设备单独设可用模型、每天额度（可以不设上限，只受整台每天总额度限制），可以暂停；库里还有到期时间，界面和命令行都没开放；没有按月的额度。控制台的设备表显示名字、是否在线或最近在线、今天用量 / 每天额度、能用的模型和开关（§10.10）。
- **管理设备**：主人可以把一台自己常带的设备（通常是手机）设为管理设备。在它上面经加密会话可以做“收紧”的操作：吊销别的设备、暂停全部、调低额度、查看用量。它不能新配对设备（必须在中心节点前完成），也不能放宽额度。丢了笔记本或别的手机时，用它马上吊销。管理设备上的这些操作需要先在本机解锁（系统生物识别）。
- `omnillm revoke <设备>` 立即生效：中心节点删除这台设备的公钥，并让 relay 关掉它的信箱。
- 每台设备一个独立信箱，信箱编号是随机数，和设备名、主人身份都没有关联。
- **relay 登记**：中心节点第一次连 relay 时，用 relay 部署者签发的登记令牌登记；只有登记过的中心节点能创建和关闭信箱，陌生人不能在 relay 上开信箱。
- **更换 relay**：中心节点经现有加密会话把新 relay 地址发给每台设备（由中心节点密钥签名），设备核对后切换，不用重新配对。
- **换电脑**：`omnillm backup` 导出一个用口令加密的备份（中心节点密钥、设备列表、额度设置、凭据），在新电脑上 `omnillm restore`。中心节点密钥没变，所有设备不用重新配对，下次连上就是新电脑。备份含凭据，导出时提醒妥善保管，恢复后旧电脑自动失效（同一时间只能有一个中心节点在线）。
- **中心节点丢了或被偷**：在管理设备上“暂停全部”，然后按控制台给出的清单到各提供商后台作废 API Key（OmniLLM 替不了这一步，清单会列出每个 Key 在哪个提供商、末 4 位），最后在新电脑上用备份恢复或重新开始。
- **设备之间不直接通信**：需要配合时（比如手机上的对话要调用另一台电脑上的 NEXA 工具），由中心节点在两条加密会话之间转接（§8.3）。

## 4. 核心技术

| 领域 | 选型 | 理由 |
|---|---|---|
| 语言 | **Go 1.25+** | 单文件、跨平台（macOS、Linux、Windows，amd64 和 arm64）、内存安全 |
| 端到端加密 | **Noise 协议**（`flynn/noise`）：IK / IKpsk2，X25519 + ChaCha20-Poly1305 + BLAKE2s | 成熟、被 WireGuard 等广泛采用的公钥握手框架，有前向保密，不自己发明协议 |
| 网页端加密 | X25519 用 WebCrypto（私钥不可导出）；ChaCha20-Poly1305 和 BLAKE2s 用 `@noble/ciphers` / `@noble/hashes`（经过审计） | WebCrypto 没有 ChaCha20，私钥又必须不可导出，所以密钥交换和对称加密分开实现；浏览器不支持 WebCrypto X25519 时拒绝使用，不退回可导出的私钥 |
| 中转传输 | WebSocket over TLS 1.3（`coder/websocket`）；relay 证书用 `x/crypto/acme/autocert` | 双方都主动外连，穿得过 NAT 和防火墙 |
| 上游出口 | `net/http` + 自写的限流、退避、熔断 | 封号防护集中在一处 |
| 存储 | 小的键值接口 `store.Store`；独立程序默认是一个 0600 的 JSON 文件（原子替换写入），NEXA 可以传自己的数据库表 | 个人规模用不上数据库；接口留给宿主 |
| 凭据存放 | `zalando/go-keyring`；无桌面环境时用 XChaCha20-Poly1305 加密文件（主密钥 32 字节，来自环境变量 `OMNILLM_MASTER_KEY`） | 用系统级保护，不自己造加密；加密文件只用标准 AEAD |
| 本机控制台认证 | 本机登录用户身份：`omnillm open` 用只有当前用户可读的一次性令牌打开控制台 | 控制台只在本机，本机用户本来就登录过了，再设密码或 Passkey 只增加步骤 |
| 通知 | macOS / Windows 系统通知；手机用 Web Push，推送内容只有“有事需要处理”，不带任何细节 | 推送经过苹果、谷歌的推送服务，所以推送里不放内容 |
| 网页客户端 | 不用框架的 JavaScript 页面 + 设备代码编译的 WebAssembly（§13.3），从独立静态地址发布；Service Worker 缓存整套文件、整套换新（签名校验还没做，§13.5） | relay 不能下发代码，否则能偷钥匙（§5.3） |
| 二维码 | `skip2/go-qrcode`，终端显示 | 配对零输入，公钥当面交换 |
| 构建与发布 | GoReleaser + cosign 签名 + SBOM（syft）+ `govulncheck` | 发布物可校验，依赖漏洞进 CI |

## 5. 安全设计

### 5.1 威胁模型

| 资产 | 主要威胁 |
|---|---|
| 账号本身 | 多 IP、多设备并发、超限、绕过限制，被提供商封号 |
| API Key 和登录会话 | 中心节点被入侵、磁盘或备份泄露、日志泄露、被设备拿走 |
| 对话内容和元数据 | **中转服务器**偷看或篡改、中间人攻击、日志留存 |
| 设备私钥 | 手机丢失、恶意网页、被替换的网页客户端代码 |
| 本机接口 | 同一台机器上的其他程序、恶意网页经浏览器打本机端口（DNS 重绑定、跨站请求） |
| 额度和钱 | 设备被盗后盗刷 |

中转服务器按“诚实但好奇、也可能被攻破”的对手来设计：它拿到的东西泄露了，也不能危及内容和凭据。

### 5.2 防封号（原则 1）

- **单一出口**：所有上游请求只从中心节点的 Provider 出口发出；设备端没有任何直连提供商的代码，CI 扫描设备端构建产物，出现提供商域名即失败。
- **像一个人在用**：一个中心节点只服务一个主人；同一提供商默认最多 2 个并发；每分钟请求数和 token 数上限低于提供商公布的限额，并按上游返回的限流响应头动态收紧。
- **人优先**：并发名额先给人正在进行的对话，后台调用（标为 `Background` 的库调用和应用令牌）排在后面，NEXA 跑判断时手机上的对话不会卡住。
- **被限流就退**：429 和 `Retry-After` 严格遵守，指数退避；连续触发进入熔断，暂停该提供商一段时间并通知主人。不重试轰炸。
- **不规避**：不轮换账号、Key、IP，不伪造客户端标识。
- **出口稳定**：记录中心节点出口所在的国家或地区，变化时暂停上游请求，等主人确认；IP 变化只记录不暂停（笔记本换网络是正常的，按 IP 暂停会让 Mac 做中心时天天被卡住）。出口地区不在提供商支持的地区清单里时，不向该提供商发请求。
- **自动化调用分开**：后台调用（库调用标为 `Background`，如 NEXA 的判断；以及所有应用令牌）默认只能走官方 API Key 和本地模型；OAuth 登录得来的订阅额度只给人手动对话用，除非该提供商条款明确允许自动化调用。后台程序用订阅额度跑批量判断，是最容易被封的用法。
- **合规凭据**：只接入官方 API Key、提供商为第三方应用开放的 OAuth 登录和本地模型；不接网页版订阅的会话 Cookie。
- **额度兜底**：每台设备和全局都有额度上限；异常用量（一小时内超过日均的 5 倍）自动暂停该设备。

### 5.3 中转服务器看不到内容（原则 2）

- **端到端加密**：所有业务消息在设备和中心节点之间用 Noise 会话加密，relay 只转发密文。
- **防冒充**：中心节点公钥只能从屏幕上的二维码拿到，设备每次连接都校验；relay 换不了公钥，也就做不了中间人。配对时的预共享密钥同样只在二维码里。
- **不让 relay 下发代码**：`omnillm connect` 和原生 App 是签名的程序。网页客户端从只给它用的静态地址（`https://omni.ixxzh.com`）发布，Service Worker 把一个版本整套缓存，新版本整套替换（不校验签名，没有实现）。替换网页可以被发现：每次发布附带网页清单 `omnillm-web-manifest.json`（构建编号和每个文件的 sha256，列在签名的 `checksums.txt` 里），`omnillm verify web` 读出线上 `app.js` 的构建编号，到最近的发布里找出构建它的那一个（没有清单的老版本读它签名的 `omnillm-web.tar.gz`），逐个文件比对；主机启动 3 分钟后和之后每天替自己的设备核对一次（`cmd/omnillm/verifyweb.go`），不一致时控制台顶部、菜单栏状态行和 `omnillm status` 的下一步都警告；没能核对（网络）不算不一致。
  - 如实说明：浏览器不会校验第一次加载的页面，所以**首次安装那一刻要信任托管方**；核对只能事后发现，挡不住第一次；只针对某一个人换网页，别人的核对也发现不了。对安全要求高的场景用 `omnillm connect` 或原生 App。
- **防重放**：握手第一条消息不带业务数据；会话内每条消息有递增编号，乱序或重复的直接丢弃并断开。
- **少留痕**：relay 不落盘、不记内容日志；公共服务的 Tengine 也不记访问日志（请求行里有信箱编号，配对期间不变，记下来就能跨网络跟踪同一台设备，`deploy/zz-relay.ixxzh.com.conf` `access_log off`）；消息按固定长度档位（如 1 / 4 / 16 / 64 KB）填充；信箱编号是随机数，和主人身份无关。
- **如实说明 relay 能看到的**：双方的 IP、连接时间、流量大小、流式回复的节奏（大致能推出回复长度）、哪些信箱在线。这些在 v1 不再进一步隐藏，文档和界面都不宣称“服务器什么都不知道”。
- **测试守住**：用一组哨兵明文跑完配对和对话，断言 relay 收到的每一帧、日志和内存快照里都找不到这组明文。

### 5.4 凭据保护：API Key 和登录会话（原则 3）

两类凭据同一套规则：**只在中心节点里存、在中心节点里用，不以任何形式发到别的设备。**

- **存放**：API Key、OAuth 的 access / refresh token 只存在系统钥匙串或加密文件里，不进普通存储、配置文件和日志；只有 Provider 出口能读，用完即弃。不接受任何网页会话 Cookie（§5.2）。
- **登录**：OAuth 授权码 + PKCE 或设备码流程由中心节点发起，回调地址是本机 `127.0.0.1`；只能在中心节点本机发起，设备无权发起登录，也无权读取、导出登录状态。
- **刷新**：token 只在中心节点刷新。刷新失败时，设备只收到“需要在中心节点重新登录”，不会收到任何 token 片段。
- **出口过滤**：返回设备的内容统一经过一个出口：只取上游的正文和必要字段，不转发上游响应头；上游原始报错改写成固定文案。
- **测试守住**：放一组哨兵凭据跑完全部功能，断言任何发往 relay 的明文（加密前）、日志、审计里都不出现哨兵值。
- **显示**：接口和管理页面永远不回显凭据，只显示末 4 位和到期时间；日志脱敏 `Authorization`、`Cookie`、`x-api-key`、`sk-*` 和 JWT 形态字符串。

### 5.5 网络暴露最小

- 中心节点**不监听任何对外端口**，只开 `127.0.0.1` 上的两个端口：本机控制台和本机应用接口。设备端 `omnillm connect` 也只监听 `127.0.0.1`。
- **本机端口也要设防**：同一台机器上的任何程序、以及浏览器里的恶意网页都能打到 `127.0.0.1`。所以：
  - 本机应用接口每个请求都要应用令牌；本机控制台要 `omnillm open` 给出的一次性令牌，换成只对本机有效的会话 Cookie（`HttpOnly; SameSite=Strict`）。
  - 校验 `Host` 头只认 `127.0.0.1` / `localhost`，防 DNS 重绑定。
  - 带 `Origin` 头的请求（来自浏览器）一律拒绝，控制台除外（控制台只认自己的来源）；不返回任何 CORS 允许头。
  - 多用户的服务器上，端口改用只有本用户能访问的 Unix 套接字。
- relay 只开 443，对未知信箱一律拒绝；连接和消息按 IP、信箱限流。

### 5.6 访问控制与防盗刷

- 设备身份就是它的公钥；吊销即删除公钥并关闭信箱。
- 每台设备有日、月额度上限，全局总额度封顶；超了直接拒绝。
- 配对密钥一次性、5 分钟过期，还要主人在中心节点上确认；配对失败多次即作废这个二维码。
- 应用令牌和设备一样，单独设模型、额度和并发，可单独吊销。
- 手机丢失时，最坏的损失是这台设备的额度：吊销即止。网页客户端和 App 可以开启本机解锁（系统生物识别），防止拿到手机的人直接用。

### 5.7 内容与隐私

- 默认不保存对话内容；审计只记元数据，而且只存在中心节点。例外是订阅对话的续接（§13.4）：对话在官方程序自己的会话文件里，只在中心节点上，一天不用、设备被移除、订阅来源被移除就删掉。
- 开启“保存历史”后，内容用中心节点主密钥加密再写库。
- 不接入任何遥测或第三方统计。

### 5.8 网页客户端安全

- 严格 CSP（服务器配置 `deploy/zz-omni.ixxzh.com.conf`）：`default-src 'none'`，脚本只认本站（加 `wasm-unsafe-eval` 给 WebAssembly），`connect-src 'self' wss:`（任何 wss 地址：自己部署连接服务、又用公共网页的人也要连得上；这条防的是注入的脚本，防不了托管方，托管方的问题靠上面的核对），不允许内联脚本和第三方资源。
- 私钥用 WebCrypto 不可导出保存；不放 URL、不放 localStorage。
- 加 `nosniff`、`no-referrer`、`frame-ancestors 'none'`、HSTS。`Permissions-Policy` 只给本站开摄像头（扫码）和麦克风（语音输入）：`camera=(self), microphone=(self)`；控制台两样都关。
- 页面标 `translate="no"`，浏览器的自动翻译不会改坏模型名、命令和配对文字（§13.3）。

### 5.9 供应链与发布

- 依赖尽量只用标准库和 `golang.org/x`；新增依赖要评审，CI 跑 `govulncheck` 和 `gosec`。
- 发布物用 cosign 签名并附 SBOM；安装脚本先校验签名再安装；网页客户端发布逐文件清单，`omnillm verify web` 和主机每天核对线上网页。
- 自动更新和手动更新走同一个安装脚本，校验和与签名照旧核对；自动更新只装比当前新的版本，新版起不来就换回旧版并跳过它（§10.7）。手动装旧版本可以，不会因此停掉自动更新。
- 发布流程不重跑测试：打标签后先确认这个提交在 CI 里已经通过（vet、`-race` 测试、staticcheck、govulncheck），没通过就停下，所以只在 CI 绿了之后打标签。
- 仓库开启 Dependabot、secret scanning 和分支保护。

### 5.10 安全默认值一览

| 项 | 默认值 |
|---|---|
| 中心节点对外端口 | 无（只开本机管理端口） |
| 中心节点和设备的通信 | 只经 relay，端到端加密 |
| 上游并发 | 每个提供商 2 |
| 收到 429 | 按 `Retry-After` 退避，连续触发熔断 |
| 出口国家 / 地区变化 | 暂停上游请求，等主人确认（IP 变化只记录） |
| 应用令牌可用的凭据 | 只有官方 API Key 和本地模型 |
| 本机接口的浏览器请求 | 拒绝 |
| 配对密钥 | 5 分钟、一次性，中心节点上确认 |
| 登录会话 | 只在中心节点存和刷新，不可导出 |
| 对话内容存储 | 关闭 |
| 单设备、单应用日额度 | 默认每天 5 美元（估算），可改，不能设成无限 |
| 并发名额 | 人的对话优先，后台程序排后 |

### 5.11 可用性

- 中心节点离线（Mac 合盖睡眠、断网）时，所有设备都用不了；设备收到明确的“中心节点离线”（本机接口返回 503），不是超时或空结果。
- 要随时可用，就把中心节点放在常开的服务器或 NAS 上；Mac 做中心时，向导会问“要不要在接电源时保持唤醒”，默认勾选，主人可以改。
- 设备上随时能看到中心节点是否在线、最后在线时间；离线时提示具体原因和办法（如“你的 Mac 可能在睡眠，唤醒后会自动恢复”），恢复后自动重连，不用手动操作。
- relay 挂了同样全部不可用；relay 是无状态的，换一台或多部署一台都不用重新配对（§3.3）。

## 6. 接口（草案）

**设备本机**（`omnillm connect` 提供，只监听 `127.0.0.1`）

| 接口 | 说明 |
|---|---|
| `GET  /v1/models` | 当前设备可用的模型 |
| `POST /v1/chat/completions` | OpenAI 兼容，支持 `stream` |
| `POST /v1/messages` | Anthropic 兼容 |

**设备 ↔ 中心节点**（经 relay，Noise 加密后的消息）：`models.list`、`chat.start`、`chat.chunk`、`chat.cancel`、`usage.get`。

**relay**：`wss://<relay>/mailbox/<信箱编号>`，只认信箱口令，只转发字节。

**中心节点本机应用接口**（仅限回环地址，要应用令牌）：和设备本机接口相同的 `/v1/*`，给同一台机器上不能嵌入库的第三方程序用（NEXA 以库嵌入，不走这里）。独立程序默认开在 `http://127.0.0.1:8765/v1`，`OMNILLM_API`（或 `hub run --api`）改地址、设成 `off` 关掉（§10.9）；安装时设的值写进后台服务，更新时和 `OMNILLM_RELAY`、`OMNILLM_WEB_APP` 一样保留（只认 `off` 和回环地址）。

**中心节点本机控制台**（仅限 `127.0.0.1`，凭 `omnillm open` 的一次性令牌）：`/console/*`，向导、设备、应用令牌、额度、Provider、登录、用量、审计。

`GET /v1/models` 的每个模型带 `x_omnillm` 字段：`locality`（`local` 表示数据不出这台机器，`remote` 表示会到云端）和 `provider`。调用方按它如实显示数据去向（嵌入库的宿主直接读 `Model.Locality`）；字段缺失时一律按 `remote` 处理。

本机接口的错误状态码（固定，调用方可以据此分支）：

| 状态码 | 含义 | 正文 `error.code` |
|---|---|---|
| 400 | 请求本身不被支持，如这个模型不支持所给的 `response_format` | `unsupported_response_format` 等 |
| 401 | 令牌缺失、无效或已吊销 | `invalid_token` |
| 403 | 令牌有效，但不允许用这个模型（不在这枚令牌的模型清单里，或该模型只能人手动使用） | `model_not_allowed` |
| 429 | 排队已满或上游限流，带 `Retry-After` | `busy` |
| 503 | 中心节点离线或连接服务不通 | `hub_offline` |

`error.message` 是给人看的一句话（中英按 `Accept-Language`），不含凭据和上游原始报错。

模型名用 `provider/model` 形式（如 `anthropic/claude-sonnet-5-5`、`ollama/qwen3`），也支持别名。界面上显示人看得懂的名字（如“Claude Sonnet 5.5”“本地 Qwen3”），并有一个默认模型，日常对话不用每次选。

## 8. 融入 NEXA（以 SDK 嵌入，不另装软件）

NEXA（`pgclient`，Go）直接引入 OmniLLM 库。用户只装 NEXA：在 NEXA 里打开“在其他设备上用”，就能把手机配对上来；NEXA 自己的判断模型也可以选 OmniLLM 管理的模型。

### 8.1 NEXA 里的两种角色

| 情况 | NEXA 嵌入 | 用户在 NEXA 里看到 |
|---|---|---|
| NEXA 所在的电脑就是主机（最常见） | `hub` | “这台电脑是主机”：接入模型、添加设备、设备列表、用量，都在 NEXA 自己的页面里 |
| 主机在别处（例如家里的 NAS 上另有一个 NEXA 或 `omnillm` 独立程序） | `device` | “连到我的主机”：扫码或粘贴配对文字，之后 NEXA 用主机上的模型 |

一个主人只有一个主机。NEXA 设置里二选一，默认“这台电脑是主机”。

### 8.2 角色一：当 NEXA 的大模型（判断模型）

- **怎么接**：NEXA 的 `omnillm` 提供方直接调用库：主机角色调 `hub.Complete`，设备角色调 `device.Complete`。不走本机 HTTP，不需要应用令牌，也不用写任何 Key 或地址到 NEXA 的配置里。
- **调用方标为后台**：NEXA 的判断是后台自动调用，每个请求都标 `Background`：只能走官方 API Key 和本地模型，不用订阅额度（§5.2）；并发名额排在人的对话后面。
- **数据去向**：NEXA 直接读 `Model.Locality`。主机角色下，本地模型（如 Ollama）是“只在本机”，云端模型是“到某某提供商”；设备角色下，所有模型都是“经主机到……”，不算本机。
- **出站走 NEXA 的出口**：库发往提供商的请求经 NEXA 传入的传输层，NEXA 的出站记录（数据去向图）里能看到每一次调用去了哪家。
- **结构化输出**：`Request` 里带 JSON Schema；模型支持就用上游的结构化输出，不支持返回 `ErrUnsupportedFormat`，NEXA 降级，不假装支持。
- **错误**：`ErrBusy`（带 `RetryAfter`）、`ErrHubOffline` 是“忙或不可用”，不能当结论（NEXA 原则 37）；`ErrModelNotAllowed` 有自己的提示语。
- **NEXA 已有的分支**（pgclient `claude/frosty-ptolemy-5ddb87`，按本机 HTTP 接口实现）里的数据去向规则、错误映射和提示语可以保留，调用方式要改成库调用（§8.4）。

### 8.3 角色二：当 NEXA 的 AI 应用

在手机上和模型对话时，模型可以调用 NEXA 的工具（查待处理事项、看今天的进展、找人等）。

- **谁在哪一步**（按原则 1、2）：
  1. 对话的模型循环在主机上跑，因为只有主机能调模型。
  2. 模型要调用 NEXA 工具时，由嵌在 NEXA 里的库执行：主机角色下就在本进程；设备角色下，主机把调用经加密会话发给那台 NEXA，再把结果加密送回。
  3. 手机只和主机说话，和 NEXA 那台电脑之间没有直连。
- **工具怎么登记**：NEXA 把自己的 MCP 工具分发器包成 `ToolHost` 传给库，每个工具带名字、参数结构、是否只读。库调用工具时走 NEXA 的这个分发器，所以 NEXA 的规则一条不少：结果里标了 `untrusted` 的内容当数据显示；被拦截的显示“已拦截”；对外动作照常弹 NEXA 自己的确认框，库不能自动确认，也不能绕过。
- **工具白名单**：在 NEXA 里勾选哪些工具可以从别的设备调用，默认只读类；不在白名单里的直接拒绝。主机被攻破时，攻击者也只能调白名单里的工具，对外动作仍要过 NEXA 的确认框。
- **不再需要** `pgclient agent setup` 登记、`omnillm ask` 命令和 stdio 方式的 `pgclient mcp`：这些是给外部程序用的，嵌入后都在进程内完成。

### 8.4 NEXA 侧需要做的事

| 事项 | 说明 |
|---|---|
| 引入 OmniLLM 库 | `go get github.com/wensuper/OmniLLM`；库的 `go` 版本要求不高于 NEXA 的 Go 1.27.2，依赖和 NEXA 现有的重合 |
| 实现宿主接口 | 钥匙串、存储、出站出口（`internal/egress`）、日志、语言、确认框和通知、工具分发 |
| `omnillm` 提供方改成库调用 | 保留已有分支里的数据去向规则、错误映射和中英提示语，把本机 HTTP 调用换成 `hub.Complete` / `device.Complete`，数据去向改读 `Model.Locality` |
| NEXA 页面加“在其他设备上用” | 主机 / 设备二选一、接入模型、添加设备（二维码、配对文字、6 位校验码）、设备列表、用量；中英双语、深浅色、375 px |
| 工具白名单设置 | 在 NEXA 里勾选可从别的设备调用的工具 |

这些改动在 NEXA 仓库按它自己的流程做和发版。OmniLLM 这边先把库的公开接口做稳（v0.1），NEXA 再接入。

## 9. 已定决策

1. **许可证**：Apache-2.0（2026-10-18）。
2. **只有中心节点和大模型交互，严防封号**：原则 1（2026-10-18）。
3. **中心节点和设备只经服务器中转，端到端非对称加密，服务器看不到内容**：原则 2（2026-10-18）。因此撤销 v0.1 里“推荐 Tailscale”和“局域网直连”的决定。
4. **客户端**：先做 `omnillm connect` 和网页客户端；网页客户端不由 relay 下发。原生 App 等需求明确后再做。
5. **融入 NEXA**：以 SDK 嵌入 NEXA，不另装软件；当 NEXA 的大模型和 AI 应用，原则 7（2026-10-18 改定，原先的“本机 HTTP + 应用令牌 + `agent setup` 登记”方式只留给第三方程序）。
6. **架构评审修正**（2026-10-18，见 §11）。
7. **产品评审修正**（2026-10-18，见 §12）：默认公共 relay、首次运行向导、本机控制台不设密码、管理设备、备份迁移、一步接入 NEXA。

## 10. 用户体验与易用性

### 10.1 第一次使用（目标 5 分钟）

1. **安装**：终端里一行 `curl -fsSL …/install.sh | sh`（或把一句话交给 AI 助手，按 INSTALL.md 装）。不问问题、不要 sudo；装好后台服务，接上本机的 Ollama，打开本机控制台。
2. **接入模型**：登录过 Claude Code / Codex 的自动接上；只有桌面版、没装或没登录的，控制台第一步的卡片看出差哪一步，点一下打开终端窗口用官方程序装好、登录（§10.8）；也可以粘贴 API Key（先发一个最小请求验证，成功才保存），或装 Ollama。
3. **加手机**：还没有设备时，安装打开的控制台直接停在二维码上（`#…&add`；之后用 `omnillm open --add` 或菜单栏「添加设备…」再打开），手机相机扫码打开网页客户端，两边核对 6 位数，在电脑上点确认。安装结果的“下一步”照着屏幕说（“浏览器里已经打开了添加手机的二维码……”），让 AI 助手转述的话和眼前看到的一致。扫码和核对数字只由人完成：INSTALL.md 规定 AI 不运行 `omnillm hub pair`、不替人确认，因为这一核对正是挡住只看到二维码的人的那道关（原则 44 的同一思路：对方的确认只在本人真的做了时才算）。
4. **对话**：手机上已经选好默认模型，直接发。

整个过程不需要服务器、不需要改路由器；命令行只在第 1 步用一次。

### 10.2 用户看到的说法

界面上（控制台、网页、菜单栏、命令行给人看的话）只用下面这些词，不出现 relay、Noise、信箱、令牌哈希等内部名词。“主机 / hub”只留在命令行帮助和开发文档里；本文档里中转服务器也照旧叫“连接服务”。

| 内部名词 | 界面上的说法 |
|---|---|
| 中心节点（hub） | 你的 Mac（说它本身时是“这台 Mac”）；中心节点不是 Mac 时，控制台说“这台电脑” |
| 设备 | 设备（只给程序和脚本用的设备另有标注） |
| 中转服务器（relay） | 远程连接（“远程连接断开 · 设备暂时连不上”） |
| 提供方（provider） | 模型来源 |
| 预算 | 每天额度；整台的叫“每天总额度” |
| 只给人用（`Interactive` 才能调） | 只能手动对话 |
| 应用令牌 | 应用（控制台「应用」页；令牌当 API Key 用） |
| 配对密钥、校验码 | 二维码、配对链接、配对文字、“6 位数一样就点「一致，添加」” |
| token 用量 | 花费（估算），token 数放在详情里 |

### 10.3 日常使用

- **手机和电脑的浏览器上**：打开主屏幕上的图标（或书签）就是对话，打开时先显示你的 Mac 上次列出的模型，马上能打字。模型选择在输入框里，按钮上的圆点表示你的 Mac 现在能不能用；电脑上左边是对话列表，底部“你的 Mac”一行写着在不在线（§13.3 网页对话的桌面版）。
- **同一台 Mac 上的程序**：控制台「应用」里添加一个应用，把它的令牌当 API Key、地址填 `http://127.0.0.1:8765/v1`（§10.9）。
- **别的电脑或服务器上的程序**：`omnillm connect` 在那台机器上开同样的本机接口，程序把地址指向它。
- **用量**：控制台「用量」看今天 / 昨天 / 最近 7 天的花费（估算，按提供商公布价格计算并标明“估算”），按设备和应用的名字列出、可按模型分、底部合计；设备和应用表里每行有“今天 / 每天额度”。
- **快到额度**：用到 80% 时提醒一次；用完时对话里直接说明“今天的额度用完了，明天恢复，或在主机上调高”，不是报错代码。

### 10.4 出问题时

每条提示都说：发生了什么、为什么、下一步（文字在 `messages.go`，等待时间按读者语言写成“约 3 小时”）。示例：

| 情况 | 提示 |
|---|---|
| 中心节点离线 | 你的 Mac 现在连不上，可能在睡眠或断网。唤醒后会自动恢复。 |
| 因地区变化暂停 | 你的 Mac 所在地区变了，为防止账号被判异常，已暂停使用模型。请在 Mac 上确认继续。 |
| 提供商限流 | Anthropic 那边正忙，约 30 秒后再试。 |
| API Key 失效 | Anthropic 的 API Key（末 4 位 a1b2）不可用：可能已失效或余额不足。请在你的 Mac 上更换。 |
| 订阅到上限 | Claude 的用量到了上限，约 3 小时后恢复。现在可以换一个用 API Key 或你的 Mac 上的模型。 |
| 模型来源被关掉 | 这个模型的来源在你的 Mac 上关掉了。在控制台“模型”里把它打开就能用。 |
| 设备被移除 | 这台设备已从你的 Mac 上移除。要继续用，在 Mac 上点“添加设备”重新添加。 |

### 10.5 丢东西和换东西

| 情况 | 怎么办 |
|---|---|
| 丢了手机 | 在主机控制台或另一台管理设备上点“移除”，立即生效；最坏损失是这台手机当天的额度 |
| 换手机 | 新手机扫码添加，旧手机移除 |
| 换电脑（主机） | 旧电脑 `omnillm backup` → 新电脑 `omnillm restore`，所有设备不用重新添加 |
| 主机丢了或被偷 | 管理设备上“暂停全部”，按清单到各提供商后台作废 Key，再用备份恢复或重新开始 |

### 10.6 语言和无障碍

- 控制台、网页客户端、菜单栏、命令行提示都中英双语。主人只选一次：菜单栏「语言 · Language」和控制台右上角的 中文/English 是同一个设置，存在中心节点里（`settings/ui_lang`），一边改了另一边几秒内跟着换；没选过时菜单栏跟随系统、控制台跟随浏览器。网页客户端跟着你的 Mac 的这个选择（不再跟浏览器），也可以在“你的 Mac”菜单里只给这台设备另选（§13.3）。命令行按终端的语言回答；后台服务用安装时记下的 `OMNILLM_LANG`。
- 网页客户端支持深浅色、375 px 窄屏、系统字号放大和读屏。

### 10.7 安装与更新（2026-10-21）

目标：装一次以后再也不用想“怎么升级”。决定和理由（自己按新用户、老用户、服务器用户各走了几轮）：

| 问题（走查时发现） | 决定 |
|---|---|
| 安装命令要先存成文件再运行，留下一个 `omnillm-install.sh`，命令也长 | 给人看的统一成 `curl -fsSL …/install.sh \| sh`。脚本全部放在 `main` 函数里、最后一行才调用，下载到一半断了什么都不执行。INSTALL.md 仍让 AI 先下载、读一遍再运行 |
| 升级只有 Mac 菜单栏一条路，还得自己点；本机这台主机停在 alpha.20 两个版本没更新 | 主机自己更新：启动 3 分钟后、之后每 6 小时查一次 GitHub 发布；有新版本就等到 10 分钟没人调用（看审计记录的最后一条），再装 |
| 自己更新会不会打断对话 | 只在 10 分钟没人用、而且没有正在出的回答和正在进行的配对时装（`Hub.Busy`）；重启几秒，手机网页和 `connect` 都会自己重连；配对中途被打断只需重新扫码 |
| 坏版本会不会自己扩散 | 走同一个安装脚本，校验和、cosign 签名照旧；`omnillm install` 先把旧程序留成 `omnillm.prev`，新版 45 秒内没起来就换回旧的（第一次安装等 15 秒）、重启服务，并把这一版记成“跳过”，以后自动更新不再装它（手动 `omnillm update` 或安装命令仍可装，装上并能运行就清掉“跳过”）|
| Linux 上主机在 systemd 里，重启服务会连带杀掉它启动的安装程序；服务的 /tmp 是私有的 | 安装程序放在主机的数据文件夹里，用 `systemd-run --user` 起一个临时单元运行（最长 15 分钟）。只带数据文件夹和语言变量，不带任何密钥（systemd-run 的命令行别的用户看得到）；自己部署的连接服务和网页地址由 `omnillm install` 从服务文件里读回来。这个单元接过更新锁，结束时写下退出码、放开锁；主机下一轮读到失败就记下来。macOS 用新会话（setsid），和菜单栏更新一样 |
| 不是服务启动的主机（没有 launchd/systemd）、自己编译的开发版 | 只查、只提示，不自己装 |
| 菜单栏、自动更新、手动命令同时触发 | 数据文件夹里一个锁文件（先写好持有者再链接到位），同时只跑一个；持有的进程或单元已经不在、或进程锁超过 20 分钟（进程号可能已被别的程序用了），视为残留。锁跟着真正干活的走：安装程序一启动，锁就改写成安装程序的进程号（Linux 上是临时单元），因为启动它的主机或菜单栏马上会被它重启；更新记录 update.log 在拿到锁之后才清空，抢不到锁的那次不会冲掉正在装的记录 |
| 一个版本装不上（网络、校验）或装上后自称的版本仍比发布旧 | 记成失败，`omnillm status` 说出来；自动更新等一天再试这一版，更新的版本出来马上试，不会每 6 小时反复装 |
| 只当设备用的 Linux 服务器没有后台服务 | `omnillm connect chat/ask` 在终端里（不是脚本）时，读上次检查的结果，有新版本提一句；结果超过一天就顺手再查一次 |
| 在服务器上照着 README 再跑一次安装命令，会把设备装成主机 | `install --device` 在设备文件夹里留一个标记（以前装的：设备文件夹加 `~/.local/bin/omnillm`）；`omnillm install` 看到它就按设备更新；要改成主机用 `--hub`。只在别处运行过程序留下的文件夹不算 |
| 人想知道有没有新版本、要不要做什么 | `omnillm update`（已是最新就直说）、`omnillm update --check`；`omnillm status` 多一行：有新版本、会在空闲时自动装，或上次自动更新失败要手动再试；`status --json` 带 `update` 字段 |
| 不想自动更新的人 | `omnillm update --auto off`（`--auto on` 打开），状态存在 `update.json`；之后只提示。`omnillm update` 后面多写了别的词就拒绝并说用法，不会意外更新 |
| README 太长，Quick Start 在“为什么”和两张表后面 | README 只留三句话、Quick Start 三步、更新、常用命令和文档表；“和别的做法比”移进 security.md，“能用哪些模型”移进 quickstart.md。中英文档分开：`README.md` / `README.zh-CN.md`，使用文档在 `docs/en/`、`docs/zh-CN/`，更新记录各一份；所有安装说明把“交给 AI 助手安装”放第一 |

网页客户端本来就在打开时自己换新版（§13），不在这里。

### 10.8 订阅的引导登录（2026-10-21）

很多人只有 Claude / ChatGPT 桌面版，或装了 Claude Code / Codex 却没登录。主机只用官方命令行程序（原则 1），所以要让“装上并登录”一步到位，而且登录始终是本人在浏览器里完成，OmniLLM 不碰登录信息。

| 情况（`Hub.SubscriptionStates`） | 控制台第一步的卡片 | 一键做的事 |
|---|---|---|
| 已登录且已接入 | ✓ 已接入 | — |
| 已登录、没接入、没被移除 | （查状态时顺手接上） | — |
| 已登录、被主人移除过 | “已登录，之前被你移除了” | 重新接入（从这里点了登录的，登录完自动接入，不用再点） |
| 装了没登录 | “已经装好，还没登录” | 打开终端窗口运行官方登录 |
| 没装，有桌面版（Claude.app、ChatGPT.app、Codex.app） | “发现 Claude 桌面版：同一个订阅……再装上官方命令行版” | 打开终端窗口：官方安装程序 → 官方登录 |
| 没装，没桌面版 | 同上，不提桌面版 | 同上 |
| Codex 登录在钥匙串里（`codex login status` 说已登录，但没有 `~/.codex/auth.json`） | “再登录一次，存成 OmniLLM 能用的方式” | 官方登录，加 `cli_auth_credentials_store="file"` |

- **怎么打开**：独立程序给控制台一个钩子（`console.Server.OpenLogin`，库自己不运行任何东西，原则 7）。macOS 上写一个只有自己能读写的 `.command` 文件，用 `open -a Terminal` 打开：不需要“控制终端”的授权，窗口里每条命令都先打印出来。其他系统给出 `omnillm login …` 让人自己运行。
- **脚本**（`loginScript`）：`set -o pipefail`（`curl … | bash` 下载失败也算失败），没装就运行官方安装程序（Claude Code：`curl -fsSL https://claude.ai/install.sh | bash`；Codex：`curl -fsSL https://chatgpt.com/codex/install.sh | CODEX_NON_INTERACTIVE=1 sh`，不然它会问“现在启动 Codex 吗”，答了“是”就进了 Codex 自己的界面、走不到登录；都装到 `~/.local/bin`，不用 sudo），先说一句“安装程序的输出里让你做的事不用管”，装完在 `~/.local/bin` 或 PATH 里确认程序在，再运行官方登录（`claude auth login --claudeai`；`codex -c 'cli_auth_credentials_store="file"' login`，没有浏览器的机器加 `--device-auth`）。每一步失败都说下一步。
- **接上**：卡片点了之后每 3 秒问一次（最多 10 分钟，页面回到前台立刻问；等待时按钮变成「重新打开」，过 45 秒再给出命令）。接上只接这一个订阅（`Hub.ConnectSubscription`，不顺手接 Ollama）。别处加了或删了来源，状态缓存立即作废，一登录好就接上、提示“已接入 Claude 订阅”，向导自己走到“添加设备”。终端里 `omnillm login claude|chatgpt` 运行同一个脚本，结束后经控制通道 `subscription.connect` 立刻接上。
- **装的时候先接上正在用的那个**：`omnillm install` 和 `omnillm status` 看自己是不是在 AI 助手里运行（Claude Code 设的 `CLAUDECODE=1`，否则顺着父进程找 `claude` / `codex`），再经控制通道 `subscription.state` 问主机这个订阅接上没有。没接上（没装在主机找得到的地方、没登录、或登录存在主机用不了的地方）且主人没有特意移除时：状态里带 `assistant`，“下一步”第一句就说它（“你在用 Codex，但 OmniLLM 还用不上它的登录……”）；有屏幕的 Mac 上安装程序直接打开同一个登录终端窗口，控制台这次不停在二维码上。这样用 Claude Code 或 Codex 装的人，至少手上这个订阅一定接上。认的时候最近的上级进程优先（Claude Code 里开的 Codex 算 Codex），`.app/Contents/` 下的桌面版不算；它跑在 API Key 或别家接口上时（`ANTHROPIC_API_KEY`、`ANTHROPIC_AUTH_TOKEN`、`ANTHROPIC_BASE_URL`、Bedrock/Vertex 开关，或 `OPENAI_API_KEY`）不问订阅登录。登录窗口只在第一次安装时打开，并且在控制台之后打开（在最前面）；窗口里登录成功后脚本自己运行 `omnillm login --connect`，不靠控制台页面开着。控制台只有在已有模型、有远程连接时才停在二维码上。
- **只输 `omnillm`**：说现在怎么样（运行行 + `nextStep` 那一句），再按“想做什么”列几条最常用的命令（加手机 `omnillm pair`、接订阅、接 API Key、看状态、更新、全部命令；有屏幕时多一条打开控制台）；只当设备用的机器列对话、问一句、换 Mac 配对；没装好就给安装命令。完整命令表还是 `omnillm help`。终端里配好一台设备后，说一屏完成：“好了：这台设备已经能用……；以后：再加手机 omnillm pair · 看状态 omnillm status · 忘了怎么用，输入 omnillm”。设备那边配对时的提示不再假定对方是 Mac（“另一边（你的 Mac 或服务器）……Mac 上点‘一致，添加’，服务器上输入 y”）。
- **没有屏幕的服务器，一条命令到手机**：`omnillm pair`（同 `omnillm hub pair`）在终端里显示二维码、核对 6 位数后输入 y。人在终端里（标准输入输出都是终端）、已有模型、还没有设备、远程连接通着时，`omnillm install`、`omnillm login claude|chatgpt`、`omnillm hub provider add` 做完都直接接着显示这个二维码，所以装好后只要一条“接上模型”的命令就能把手机加进来；“下一步”也这么说。AI 助手运行时不会这样做（不是终端，或认出是 Claude Code / Codex，哪怕它用伪终端跑命令），配对和登录都留给人（INSTALL.md 第 6、7 条）；这一步配不成（过期、选了不一致、Ctrl-C）只说一句“以后运行 omnillm pair”，前面的安装、登录照样算成功。“没有屏幕”按 `headless()`：Linux 上没有 DISPLAY / WAYLAND_DISPLAY，Mac 上是 SSH 进来的会话。登录窗口里的 `omnillm login --connect` 用默认数据目录，自定义 `OMNILLM_HOME` 的实例靠控制台页面接上。状态里的 `console_opened`、`login_opened` 告诉 AI 屏幕上现在是什么。只当设备用的机器拒绝运行（订阅要登录在主机上）。
- **提示文字**：安装结束和 `omnillm status` 在没有模型时，订阅那两行直接给 `omnillm login claude` / `omnillm login chatgpt`；发现桌面版时第一行先说“发现 Claude 桌面版：同一个订阅也能给手机用”。
- **为什么不直接用桌面版自带的程序**：Claude 桌面版和 ChatGPT 桌面版里都带着一份命令行程序，但路径随版本变、不是给外部用的，登录也各自分开；装官方命令行版是最稳的一条路，一分钟。
- **查状态的开销**：每看一次要运行几次官方程序，`SubscriptionStates` 的结果复用 2 秒，用自己的超时（关掉的页面不会留下半截结果）；会碰到钥匙串的 Codex 自查（`CodexLoggedInOwn`）30 秒最多一次。
- **付费计划**：卡片写明需要 Claude Pro / Max、ChatGPT 付费订阅；Claude 登录失败时先提这一条。
- **不是 Mac 时**：控制台不开窗口（钩子只在 macOS 设置），卡片直接给出 `omnillm login …`，并照样等它接上。

### 10.9 应用的本机接口默认打开（2026-10-21）

控制台的「应用」能发令牌，但装好的主机启动时没有带 `--api`，本机接口根本没开，令牌用不上，页面也不说连哪里。现在：主机默认在 `127.0.0.1:8765` 开本机接口（`OMNILLM_API` 可以改地址或设成 `off`；端口被占时只记日志、不影响别的）；独立程序先占住端口，再把真实地址告诉控制台（`console.Server.APIURL`），控制台只在接口真的在时显示地址。「应用」页顶上只有一句说明，旁边的「?」点开是接入方式（接口地址可复制、Key 用应用的令牌、兼容 OpenAI 也支持 Anthropic、只有本机程序连得上），点别处、Esc 或滚动就收起；接口没开时，页面直接显示原因，不藏在「?」里；添加应用后令牌旁边给出 `OPENAI_BASE_URL` / `OPENAI_API_KEY` 两行和一条 `curl …/models` 试用命令。接口本身不变：只听回环地址、每个请求都要令牌、带 `Origin` 的（网页发的）一律拒绝、Host 必须是本机名。

### 10.10 控制台的设备、应用和模型来源（2026-10-22）

设备、应用、模型来源三张表用同一套做法：每行一个开关管“在不在用”，改别的进编辑框，删除是不显眼的文字按钮并且先问。

- **设备和应用表**：名字、（设备）最近在线、今天 / 每天额度、模型、开关、编辑。除名字外每列都定成刚好放下的宽度，剩下的都给名字；名字还放不下时截短，鼠标停上去看全名（见下面的小卡片）。窗口窄到 600 px 以下时每行叠起来：名字下面一行写在线或最近在线、今天用量和模型。
- **“模型”一列**：能用的全部开着时写“全部 N 个”，只开了一部分写“部分 m / n”（紫色），一个都用不了写“—”。“能用的”按对象算：设备不算设成不在设备上显示的和来源关掉的，只给程序用的设备和应用再不算只能手动对话的（应用也不算订阅）。保存的清单为空、或清单里包含它能用的每一个，都算“全部”。
- **小卡片**：名字和“模型”一格，鼠标停上去（或用键盘选中）出一张卡片。名字那张写类型（只有知道的才写：只给程序用的设备、应用）、添加时间、最近在线（在线时标在标题旁）、今天用量；模型那张按来源列出它能用的模型，没开的标“没开”，“全部”时注明以后接入的也自动可用。离开、Esc、滚动就关；卡片开着、编辑框开着或正在问话时，每 10 秒的刷新先等着，不会把正在看的东西收走。
- **开关**：关掉即暂停（`Paused`），它的下一个请求和模型列表都得到 `device_paused`，手机显示暂停提示；配对、令牌和设置都保留，打开马上恢复。
- **编辑框**：名字、开启、每天额度（或“不设上限”）、能用的模型、移除。模型部分上面是“全部模型（以后接入的新模型也自动可用）”开关，下面按 订阅 / API Key / 这台 Mac 分组，每个模型一个开关，全都能直接点：“全部模型”开着时下面每个都显示为开；关掉其中一个，“全部模型”跟着关、其余保持开；把最后一个关着的打开，又变回“全部模型”（存成空清单，以后接入的也算）。它用不了的模型开关是灰的并写明原因；一个都不选时不能保存。
- **模型来源表**：来源名字、接入方式（订阅登录 / API Key 末 4 位 / 只在这台 Mac 上）、最近的问题（登录失效、到上限及恢复时间）、「开启」开关、「移除」。开关就是 `Hub.SetProviderOff`（存在 `settings/source_off/<名字>`，命令行 `omnillm hub provider off|on <来源>`，`hub providers` 显示“已关闭”）：登录和 API Key 都不动，它的模型整行变灰、标“来源已关闭”，不进设备和应用的列表，设备调用时得到“没有这个模型”，应用得到 `MsgSourceOff`。「移除」会删掉 Key，所以做成红色文字按钮，点了在这一行里再问一次。
- **“只能手动对话”**：「模型」页顶上一句说明（只能人手动对话，脚本和应用调用不了；订阅模型一律如此，免得账号被当成自动化）。把一个模型设成“只能手动对话”（「模型」页的开关或编辑框）之前，先算出会因此用不了它的应用和只给程序用的设备（`chatOnlyLosers`），有的话弹框列出名字，标出哪个会因为只剩这一个模型而完全停下，主人点“仍然打开”才改；取消、Esc、点框外都不改。没人受影响时直接改。起因：zc 的两个应用和 pgserver-139 只用 qwen3-32b，它被一下点成“只能手动对话”后全部悄悄断了。
- **添加设备面板**见 §3.2；「应用」页见 §10.9。

### 13.3 v0.2：订阅共享和免安装设备（2026-10-19）

目标：Mac 上已经登录的 Claude 或 ChatGPT 订阅，手机、平板、Linux 服务器都能顺畅地用；除了 Mac，别的地方尽量不装东西。

**订阅（中心节点）**

- 新增两种提供方 `claude-code`、`codex`：中心节点运行主人已经登录的官方程序（`claude -p`、`codex exec`），把它当纯文本模型。Claude：`--tools ""`、`--strict-mcp-config`、`--setting-sources ""`、`--no-session-persistence`（人的对话改为续接会话，见 §13.4），系统提示用 `--system-prompt=…` 一个参数传。Codex：只读沙箱、`--ignore-user-config`、`--ephemeral`（同上），关掉 shell、代码模式、插件、浏览器、联网搜索等所有工具。都在空的临时目录里跑，环境变量只给 HOME、PATH、语言和临时目录，中心节点的主密钥、relay 令牌、代理都不传。实测：设备发来“运行命令、读文件”的文字，两个程序都只能回答“没有工具”。
- 登录留在官方程序里（钥匙串或它自己的文件），中心节点只问它“登录了吗”（`claude auth status`、`codex login status`），从不读取。登录失效时设备看到“请在主机上运行 claude 重新登录”。
- 防封号：订阅模型一律只限人用（Interactive），后台调用、应用令牌、设备本机接口都用不了，主人也关不掉；一次只跑一个、每分钟最多 12 次、排队最多 4 个；Claude 报告用量到顶（`rate_limit_event`）就按它给的恢复时间暂停整个提供方，不再发请求。
- 自动接入：安装时、中心节点启动时、`omnillm status` 和控制台打开时，发现已登录的 Claude Code / Codex 就接上。模型：Claude 的 sonnet、opus、haiku（跟着 Claude Code 的最新版本走）和 Codex 默认模型，价格记 0（订阅已付）。

**手机和平板：网页客户端，不装 App**

- 配对二维码里是一个链接：`<网页客户端>#pair=<配对文字>`。相机扫码直接打开网页，配对文字在 `#` 后面，浏览器不会把它发给网页托管方；网页一打开就把它从地址栏和历史里抹掉。
- 网页里跑的是和 `omnillm connect` 同一份设备代码，编译成 WebAssembly（gzip 后约 1.35 MB，见下面“首次打开的大小”），加密全在里面做。配对状态（设备私钥等）存在 IndexedDB，用浏览器生成的、不可导出的 AES-GCM 密钥加密；对话记录同样加密保存。
- 浏览器不能给 WebSocket 加请求头，也读不到 HTTP 状态：relay 为浏览器开一条路，信箱口令放在子协议 `omnillm.auth.<口令>` 里，只接受登记过的网页来源（默认 `https://omni.ixxzh.com`）；口令不对、信箱不存在、主机不在线一律接受后用 4404 关闭，成功的先收到一帧 `ready`。主机的连接仍然拒绝任何浏览器。
- 发布：网页客户端随程序一起在打标签的发布里构建（`omnillm-web.tar.gz`，校验和由 cosign 签名），放在只给它用的 `https://omni.ixxzh.com`（zc 10-19 定，见 docs/relay-deploy.md）；Service Worker 把整套文件缓存住，新版本整套替换。首次打开要信任托管方（§5.3 已说明）；签名更新留到以后。
- 从主屏幕打开的网页应用和 Safari 的存储是分开的，所以网页里也能用摄像头扫码（jsQR）或粘贴配对文字。
- 首次打开的大小（2026-10-20）：服务器约 500 KB/s，手机第一次打开要下完整个 WebAssembly。浏览器版（`GOOS=js`）只编译设备需要的部分：连信箱直接用浏览器自带的 WebSocket（`syscall/js`，子协议、`ready` 帧、4404 和原来一样），不链接 `net/http`（TLS、证书、MIME 等）和 WebSocket 库；图片只按文件开头核对格式，PNG、GIF 从固定的头部读尺寸，JPEG、WebP 的尺寸留给中心节点（它对每张图都解码头部再用）；`encoding/json` 用经典实现（`GOEXPERIMENT=nojsonv2`，行为相同）。原生程序和公开接口不变：`device.Options.Transport` 在原生构建里仍是 `http.RoundTripper`，浏览器里不用。结果：8.2 MB → 4.7 MB，gzip 2.24 MB → 1.35 MB。

**配对文字的紧凑格式（v0.2.0-alpha.4，alpha.5 加校验）**：`omnillm3-` + base64url(SHA-256 前 4 字节 | 过期时间 4 字节 | 信箱 16 | 信箱口令 32 | 中心节点公钥 32 | 一次性配对密钥 32 | relay 地址)，比 JSON 的 `omnillm1-` 短约四成，二维码明显更稀、更好扫；粘贴损坏的文字靠校验马上被认出来。`omnillm1-`、`omnillm2-`（无校验）都还认。网页客户端必须先于中心节点升级，否则旧网页认不出新格式。

**文字 + 图片（v0.2.0-alpha.2）**

- 消息可以带图片（PNG、JPEG、GIF、WebP；每张 ≤ 2 MB，每条 ≤ 4 张，一次请求文字加图片 ≤ 5 MB，加密消息仍在 8 MB 以内）。中心节点按文件开头的字节核对格式，和声明不符就拒绝。
- 去向：OpenAI 兼容接口用 `image_url`（data: 网址），Anthropic 用 base64 图片块；Claude Code 用 `--input-format stream-json` 把图片放在输入里（不需要读文件的工具）；Codex 把图片写进本次调用的私有临时目录，用 `-i` 附上，调用结束即删。本机接口只收内联图片，不替程序去下载网址（防止中心节点被当成取任意网址的跳板）。
- 手机网页在发送前把照片缩到长边 1600 像素、转成 JPEG（2 MB 以内），小 GIF 原样发。

**Linux 服务器：一个程序，不装服务**

- `install.sh --device`（或 `omnillm install --device`）只把程序放到 `~/.local/bin`，不装后台服务，然后在终端里提示粘贴配对文字。服务器没有钥匙串，设备私钥加密存在数据目录里，主密钥在旁边 0600 的文件里（和中心节点在 Linux 上一样）。
- 人在终端里用 `omnillm connect chat`（多轮对话，Ctrl-C 只停这次回答）和 `omnillm connect ask`（不用指定模型，默认 Claude Sonnet）；脚本走本机接口，只看得到、也只能用非订阅的模型。

**安全审查后补的（2026-10-19）**

- Codex 不管加什么参数都会读主人的 `~/.codex/AGENTS.md`（实测会被设备问出来）。中心节点改为让 Codex 在自己的目录（`OmniLLM/codex-home`）里跑：里面只有一个指向主人 `auth.json` 的链接和一个空配置，没有主人的说明文件和设置。只有一份登录、一份刷新令牌（Codex 刷新时原地改写文件，链接不断），两边不会互相登出。Claude Code 在现有参数下不读 CLAUDE.md（实测）。
- 关工具靠的是官方程序认这些参数。所以每个新版本先过一道检查：让它运行命令、读一个临时文件，只要做到了一样，这个版本就不用，设备看到“请更新 OmniLLM”。检查在接入和启动时在后台跑，人的第一条消息不用等。
- “有人在等”是设备自己说的：`omnillm connect ask/chat` 只有在终端里（标准输入输出都是终端）才算人，管道、cron、脚本一律算后台，用不了订阅；网页客户端是人打字。中心节点再按设备限速：订阅模型每台设备每小时 60 次、每天 300 次，超过就提示稍后再试，免得一台被脚本控制的设备把账号用成自动化的样子。
- 节奏：订阅每分钟 12 次的额度用完时，20 秒内能轮到的请求就等一下再发，不报错；更久的才提示“为了像一个人在用，请隔开一点”。
- 配对链接谁都能发。从地址栏打开的链接（扫码或点开），网页配对前先显示它通向哪个连接服务，人点“添加”才继续。人自己在网页里粘贴的（链接或配对文字）是本人的动作，点“添加”后直接出 6 位数，不再多问一次；只有这台设备已经配对过时才问，提示会替换掉之前的配对。网页不允许被嵌进别的页面。
- 被移除的设备：以前它只会看到“连不上主机”（经过 relay 看，移除和睡眠一样）。现在中心节点把移除的设备留 30 天的记录：它再连上来，先证明自己的密钥，然后在加密会话里被告知“已被移除”，网页随即清掉配对。
- 设备本机接口和应用令牌看不到订阅模型；Linux 上有可用的钥匙串时仍用钥匙串，没有时才用数据目录里的密钥文件。
- 网页客户端用只给它用的域名 `omni.ixxzh.com`（不再用 GitHub Pages：那个域名下别的 Pages 项目和它同源，能读它的存储）。Service Worker 还不校验更新的签名，写在这里。

**易用性走查后补的（2026-10-20，v0.2.0-alpha.8）**

- `~/.local/bin` 不在新 Mac 的 PATH 里：安装时如果终端按名字找不到 `omnillm`，在 shell 启动文件（zsh 的 `~/.zshrc`、bash 的 `~/.bashrc` 或 macOS 的 `~/.bash_profile`、fish、其他 `~/.profile`）末尾追加一行，只加一次；这次安装打印的下一步命令用完整路径，保证照着能运行。
- 后台服务没有 LANG：安装时把装的人用的语言写进服务的 `OMNILLM_LANG`，`omnillm hub pair` 的问题、配对文字、报错和日志才是中文。安装脚本的提示也跟语言走，每句说清下一步；INSTALL.md 的对照表同时列出中英两种说法。
- 网页客户端把模型常写的 Markdown（标题、`**粗体**`、行内代码、列表）显示成格式，全部用文字节点生成，不解析 HTML。
- 被移除的手机不用等到发消息才知道：页面回到前台时和打开期间每两分钟，静默向主机取一次模型列表；被移除就清掉配对和对话并说明原因（顺带拿到新接入的模型）。
- 终端配对时的 6 位数按“123 456”显示；配对成功说这台设备在主机上叫什么，不再显示设备 ID。

**真手机试用后补的（2026-10-20，v0.2.0-alpha.14–16）**

- 网页载入不会一直转：显示正在哪一步和下载进度；20 秒没有进展就说明停在哪一步，给“重新载入”（清掉 Service Worker 和缓存）；载入出错或程序退出直接显示原因。
- 设备遇到“主机连不上”时：主机一分钟内回过话，就在约 10 秒内再试几次（连接服务重启、主机重新登记都在这个时间内）；否则一次快速重试后就报告。只有主机没确认收到的请求才会被判为“连不上”，重发不会重复执行。
- 每条回答带上回答它的模型名；“订阅”只指 claude-code / codex 提供方，不再等同于“只给人用”。
- 外观与 NEXA 一致：配色、字号、圆角、阴影、聚焦都取自 NEXA 的 Aurora（pgclient `web/static/app.css`，docs/32）；图标与 NEXA 同一家族。

**多轮产品评审后补的（2026-10-21，v0.2.0-alpha.23；alpha.22 从另一条分支发出，不含这些）**

五个视角（新手、日常使用、视觉对照 NEXA、出错与边界、中英文案）各评审多轮，每轮全量截图（`omnillm-testkit/fullshots.mjs`），修复方案写在 `omnillm-testkit/review/FIXPLAN-r*.md`。定下来的规则：

- 用词：给人看的地方一律叫“你的 Mac / 这台 Mac”（不说主机/hub），“远程连接”（不说连接服务/relay），“模型来源”（不说提供方），“每天额度”（不说预算），“API Key”。主机/hub 只留在命令行帮助和开发文档里。品牌口号不翻译。
- 错误：`Error.Args` 只带种类（`claude-code`、`codex`、提供方名字），不带英文显示名或英文时长；等待时间来自 `RetryAfter`，由 `Describe(lang)` 按读者语言写成“约 3 小时”。每句报错都说下一步怎么做。订阅到上限后的冷却期间仍然报“到上限”（带“换个模型”的建议），而不是“稍等”。

**网页对话的桌面版（2026-10-22，v0.2.0-alpha.36；语音输入 alpha.37，不让翻译和标签页自己接过来 alpha.38，打开就显示上次的模型 alpha.39）**

- **排法**：≥1024 px 左边是 272 px 的侧栏（标志、新对话、搜索、按 今天/昨天/前 7 天/更早 分组的对话列表、底部“你的 Mac”），右边没有顶栏；对话和输入框在同一条居中的栏里，正文最宽 704 px（`--col`），窗口再宽只多留白。侧栏可以收起（记在这台设备上），收起后左上角留“展开侧栏”和“新对话”。768–1023 px 和手机上侧栏是抽屉，顶栏是“对话列表 / 对话标题 / 新对话”。浏览器标签页标题是“对话标题 · OmniLLM”。
- **消息**：回答不再是卡片，直接排在页面上；只有自己的话是气泡（栏内靠右，最宽占栏宽 82%）。代码块有一条标题栏：语言名和“复制”。

- **语音输入**：浏览器有语音识别（`SpeechRecognition` / `webkitSpeechRecognition`，Chrome、Edge、Safari）时，发送按钮左边出现麦克风；没有就不显示。点一下开始（连续识别、显示中间结果，语言跟页面），文字接在已经打的字后面、边听边写进输入框，每次都从全部结果重拼，浏览器重复上报也不会多字；再点、Esc、打字、发送、切到别的标签页或 6 秒没听到新内容就结束；发送时先放弃识别，发出去的是输入框里此刻的字。识别出的字从不自动发送。正在听：麦克风变成五根跳动的声波（减弱动态时静止），输入框紫色描边，占位文字“正在听，说完再点一下……”。第一次用时提示一次声音交给谁识别（Google / Apple），没有麦克风权限、没听到、没网各有一句话。网页的 `Permissions-Policy` 要允许 `microphone=(self)`。

- **快捷键**（Mac 用 ⌘，其他系统 Ctrl）：⌘⇧O 新对话、⌘K 搜索、⌘\ 收起侧栏、Esc 停止回答（菜单开着时先关菜单，输入法选词时不管）、⌘⇧; 复制最后一条回答、/ 跳到输入框、⌘/ 快捷键表。不用浏览器自己占的键（⌘N、⌘T、⌘W、⌘⇧C）。回车：有鼠标的电脑上 Enter 发送、Shift+Enter 换行，手机上 Enter 换行、用发送按钮发；输入法选词的回车不发送（Safari 只报 `keyCode` 229，也认）；回答进行中 Enter 只提示等它说完，停止只能点停止或按 Esc。

### 13.4 订阅对话续接（2026-10-21）

以前每说一句，中心节点都启动一个新的 `claude` / `codex`，把整段对话拼成一段文字重发。对话越长，输入越多、首字越慢、订阅额度用得越快。现在人的对话续接官方程序自己的会话，只发新的一句。

- **认出“接着上一句”**：线路上什么都不变，设备照旧发整段对话。中心节点按“谁问的（设备或主机自己）+ 哪个程序 + 模型 + 系统提示 + 新的一句之前的全部对话”算一个哈希，和上一轮结束时记下的对上，才续接。任何一项不同（改了前面任何一句、重新生成、换了模型、另一台设备），就从整段对话开新会话，和以前一样。上一句用户的话连图片一起算；更早的只算文字，因为网页客户端只带最近两轮的图片，更早的换成“[N earlier image(s)]”，哈希时去掉这个说明。所以续接不会接错对话，也不需要设备改代码、不需要对话编号。
- **怎么续接**：Claude Code 第一轮用 `--session-id <中心节点生成的 UUID>`，之后 `--resume <id>`；在中心节点自己的空目录 `OmniLLM/claude-chats` 里运行（Claude Code 按目录找会话，所以目录固定），会话文件在 `~/.claude/projects/<这个目录>/` 下，和主人自己的项目分开；中心节点按会话编号（随机 UUID）找这个文件，不自己推算 Claude 的目录命名。Codex 第一轮去掉 `--ephemeral`，启动后先读第一行 `thread.started` 拿到会话编号再把回答交出去（这样刚开始就被取消的一轮也知道要删哪个会话），之后 `codex exec resume <id>`（它不收 `--sandbox`，改用 `-c sandbox_mode="read-only"`，关工具的参数照旧）；会话在中心节点自己的 Codex 目录 `OmniLLM/codex-home` 里。续接时只把新的一句（和它的图片）交给程序。实测：续接时两个程序照样没有工具（让 Codex 运行命令，它回答工具被关掉了，标记文件没出现）。
- **只给人的对话**：只有 `Interactive` 的订阅调用续接；后台调用本来就用不了订阅，版本探测和工具检查仍然 `--ephemeral` / `--no-session-persistence`。
- **一轮只占一个会话**：续接时先把记录从表里取走，这一轮正常结束才按新的哈希放回去；出错、被取消、超时就删掉这个会话，下一句从整段对话重来。会话文件不在了（被人删了）也直接重来，不报错。同一个位置又出现一个新会话（同样的开头又问了一遍），留新的、删旧的。一轮进行中设备或订阅来源被移除，这一轮结束后什么都不留。
- **其他结束方式**：一轮被暂停设备、中心节点停止、出口地区变化打断，和出错一样删掉这个会话。“再回答一次”在同一位置产生新会话时，旧的由新会话替换并删除；没被替换的（问法改了）等一天后的清理。
- **卸载**：`omnillm uninstall`（不管加不加 `--purge`）都删掉中心节点记着的全部会话和 `claude-chats` 目录；`--purge` 另外删 `codex-home`。
- **什么时候删**：一天没用；同一台设备超过 20 个、全部超过 100 个时删最旧的；设备被移除（`Revoke`，包括手机自己断开）删它的全部；订阅来源被移除删那个程序的全部。删除在后台做（移除设备不等它）：Claude 删会话文件；Codex 运行 `codex delete --force <id>`（会话文件和它数据库里的记录一起删），失败也删文件。实测 Claude 在 `~/.claude` 下没有别的文件带这个会话编号。中心节点启动时和之后每小时检查一次。
- **表里没有内容**：表存在中心节点的 `Store`（`chats/index`），只有哈希、程序的会话编号、属于谁、最后使用时间。会话编号一知道就先记成“进行中”，所以中心节点在一轮中途退出，下次启动也能找到并删掉（15 分钟后）。中心节点只删表里记着的会话，不扫目录删“认不出”的文件，免得和别的中心节点（如嵌入 NEXA 的那个）或主人自己的会话互相误删。
- **如实说明**：会话文件是官方程序自己的格式，明文，权限和主人自己的 Claude / Codex 历史一样，只在中心节点上，不经过 relay、不到设备。原则 4 “对话内容默认不保存”为此加了这一条例外（zc 10-21 定：用省下的 token 和更快的回答，换中心节点上最多一天的对话留存）。Codex 删除会话后，它的 SQLite 数据库空闲页里可能残留文字，直到被覆盖。
- **测试**：`internal/provider/chats_test.go`（续接、改了更早的话重来、别的设备不续接、失败即删、文件没了重来、限额和过期、同一位置的旧会话被删、进行中被移除的设备不留、哈希覆盖每一项且图片换成说明后仍接得上、Codex 续接和删除、刚开始就被取消的 Codex 一轮也删掉、两种程序的后台调用都不留）、`hub/chats_test.go`（设备对话续接，移除设备、移除订阅来源后文件都没了）；`OMNILLM_REAL_CLI=1 go test -run TestRealChatContinues ./internal/provider` 用真的 Claude Code 和 Codex 验证第二句记得第一句、用的是同一个会话、删除后不留文件。hub 的测试把 `HOME`、`OMNILLM_HOME` 指向临时目录，不碰真实的会话。
