# 安全说明

[English](../en/security.md) | 简体中文

这份文档写给使用者：OmniLLM 保护什么、怎么保护、**不**保护什么。实现细节见[设计文档](../design.md)第 3、5 节，不能违背的规则见[原则](../principles.md)。

## 结论先说

- 你的**账号**（订阅登录、API Key）只在主机上，不会发到任何设备，也不会经过连接服务。
- 你的**对话**在设备和主机之间端到端加密。连接服务，包括项目提供的公共连接服务，看不到内容，也冒充不了你的主机。
- 你的**订阅**只给人手动对话用，而且按一个人的节奏使用，尽量不让提供商觉得账号被共享或被自动化滥用。
- 主机被入侵、手机解锁后被人拿走、网页托管方作恶，这几种情况保护有限，下面逐条写明。

## 谁能看到什么

| 谁 | 能看到 | 看不到、做不到 |
|---|---|---|
| **模型提供商**（Anthropic、OpenAI 等） | 你发给模型的内容。这和你直接用它们一样 | 你有几台设备、设备在哪；所有请求都从主机发出 |
| **连接服务**（公共的或你自己部署的） | 主机和设备的 IP、连接时间、每条消息的大致大小和节奏、哪些设备在线 | 对话内容、图片、模型名、用量、设备名、任何凭据。它也换不了主机的公钥，所以做不了中间人 |
| **网络上的其他人**（公共 Wi-Fi、运营商） | 你在连 `relay.ixxzh.com`（TLS 加密） | 其余和连接服务一样，而且还多一层 TLS |
| **只拍到了二维码的人** | 无 | 配不上：二维码 5 分钟过期、只能用一次，最后还要你在主机前核对 6 位数并点确认 |
| **拿到了你手机的人** | 手机上能打开的东西，包括保存在手机上的对话记录 | 你的账号和 Key；也超不出这台设备的额度。你在主机上「移除」它，它立即失效，再打开时会被告知已移除并清掉配对 |
| **主机上的其他程序、你打开的恶意网页** | 无 | 本机接口只开在 `127.0.0.1`，每个请求要令牌，带浏览器来源的请求一律拒绝，`Host` 头不对也拒绝（防 DNS 重绑定）；控制台要一次性登录链接 |
| **设备上用 OmniLLM 的人** | 模型的回答 | 让主机运行命令、读写文件、上网：订阅模型被调用时关掉了所有工具 |
| **能控制主机的人**（主机被入侵） | 一切 | 这是 OmniLLM 保护不了的：账号就在主机上 |

## 加密和配对

- **端到端加密**：主机和每台设备各有一对长期密钥。每次连接用 [Noise 协议](https://noiseprotocol.org)的 IK 模式握手（X25519 密钥交换、ChaCha20-Poly1305 加密、BLAKE2s 哈希；WireGuard 用的也是这一套），会话密钥每次重新协商，有前向保密：今天的密钥泄露了，解不开以前录下的流量。会话每小时或每 100 万条消息自动换钥。
- **防重放、防篡改**：握手的第一条消息不带任何请求，被录下来重放也触发不了调用。每条消息有严格递增的编号，被改动、重复或乱序的消息直接丢弃并断开。
- **长度也做了处理**：消息按 1 / 4 / 16 / 64 KB 几个档位补齐，连接服务从大小只能看出大概量级。
- **公钥只能当面交换**：主机的公钥放在二维码或配对文字里，由你从主机屏幕带到设备上，从不经过连接服务。设备之后每次连接都核对这个公钥。
- **配对要你确认**：二维码里还有一个一次性配对密钥（256 位随机数，5 分钟过期）。握手完成后，两边屏幕显示同一个 6 位数，由握手结果算出，你核对一致后在主机上点确认才算配对成功。确认只能在主机上做。
- **配对文字带校验**：复制时少了或错了一个字符，会马上提示“配对文字不完整或被改动了”，不会连到别处。
- **配对链接先问再连**：别人发给你的配对链接，网页会先说明它通向哪个连接服务，你点「添加」才继续；这台设备已经配对过的，还会提示它会替换掉现在的配对。

## 账号和凭据

- **订阅**：Claude 和 ChatGPT 的订阅通过主机上官方的 Claude Code 和 Codex 使用。你在官方程序里自己登录，登录留在那里（系统钥匙串或它自己的文件）。OmniLLM 只问它“登录了吗”，不读取、不复制、不刷新登录信息。OmniLLM 不使用网页版订阅的 Cookie，也不抓取网页登录信息。
- **API Key**：只在主机的系统钥匙串里（Linux 上没有钥匙串时，存在只有你能读的加密文件里，密钥文件单独放）。控制台只显示末 4 位。Key 只能在控制台或主机终端里输入，不能写在命令行参数里，因为参数会留在 shell 历史里。
- **不外传**：发往设备的只有模型回答的正文。上游的响应头、原始报错都不转发，报错改写成固定的说明。日志自动打码 `Authorization`、`x-api-key`、`sk-…`、JWT 形态的字符串和配对文字。
- **测试守着**：测试用一组“哨兵”凭据和明文跑完配对和对话，断言连接服务收到的每个字节、日志、磁盘上的文件里都找不到它们。

## 订阅模型被关在什么样的笼子里

Claude Code 和 Codex 本来是能运行命令、读写文件的编程助手。主机调用它们时只把它们当纯文本模型用：

- **关掉所有工具**：Claude Code 不给任何工具、不连 MCP、不读你的设置；Codex 只读沙箱，关掉 shell、插件、浏览器、联网搜索等全部功能，也不读你的配置。
- **不读你的私人说明**：Codex 在 OmniLLM 自己的目录里运行，读不到你 `~/.codex/AGENTS.md` 里写给它的个人说明。
- **干净的环境**：在一个空的临时目录里运行，只给它 HOME、PATH、语言和临时目录这几个环境变量；主机自己的密钥、连接服务令牌、代理设置都不传。
- **新版本先过检查**：工具关不关得掉，取决于官方程序认不认这些参数。所以每遇到一个新版本，主机先在后台让它试着运行命令、读一个临时文件，只要做到了其中一样，这个版本就不用，设备上会提示“请更新 OmniLLM”。
- **图片先查再用**：只收 PNG、JPEG、GIF、WebP；按文件开头的字节核对格式；拦下“几 KB 却声称几十亿像素”的图片（单边不超过 8192 像素，总共不超过约 4000 万像素）；每张不超过 2 MB。本机接口只收直接附带的图片，不替程序去下载网址，免得主机被当成访问任意网址的跳板。

## 尽量不被封号

提供商封号通常是因为看起来像账号共享、自动化滥用或规避限制。OmniLLM 的规则写在代码里，主人也放不宽：

| 风险 | 规则 |
|---|---|
| 看起来像多人共享 | 所有请求都从主机这一台电脑发出；一个主机只服务一个主人和他自己的设备，没有“分享给别人”的功能 |
| 看起来像自动化 | 订阅只给人手动对话用：网页客户端是人打字；终端里的 `connect chat` / `ask` 只有在真正的终端里才算人，管道、cron、脚本一律算后台程序。后台程序、应用令牌、设备上的本机接口都看不到订阅模型 |
| 请求太密 | 订阅模型一次只跑一个请求，每分钟最多 12 次，排队最多 4 个；每台设备每小时最多 60 次、每天 300 次 |
| 被限流后继续发 | 遵守 `Retry-After` 和订阅的用量上限提示，按提供商给的恢复时间暂停整个提供商，不重试轰炸 |
| 规避限制 | 不轮换账号、不轮换 Key、不换 IP、不伪造客户端标识 |

这些规则降低风险，但**不能保证**不被封号：最终由提供商的条款和判断决定。请遵守你所用提供商的使用条款。

## 手机上的网页客户端

- **加密在手机上做**：网页里运行的是和命令行客户端同一份代码（编译成 WebAssembly），加解密都在手机上完成。
- **存储加密**：配对信息（设备私钥等）和对话记录存在浏览器的 IndexedDB 里，用浏览器生成的、**不可导出**的 AES-GCM 密钥加密。
- **网页本身的防护**：严格的内容安全策略（只运行本站的脚本，不加载任何第三方脚本、样式或资源，不允许内联脚本），禁止被嵌入别的页面，不发 Referer。
- **单独的域名**：网页客户端放在只给它用的 `omni.ixxzh.com`，同源下没有别的网站能读它的存储。
- **配对文字不进服务器日志**：二维码链接里的配对文字放在 `#` 后面，浏览器不会把它发给网页服务器；网页打开后立即把它从地址栏和历史记录里抹掉。

**要知道的限制**：浏览器不会校验第一次加载的网页代码。托管网页的服务器如果被攻破或作恶，就能给之后打开它的设备下发恶意代码。我们的应对：

- 网页只从 GitHub 上签了名的发布包部署，服务器上不手改；文件归 root 所有、只读，连接服务以无权限的独立账号运行，即使连接服务被攻破，也改不了网页。
- 网页缓存后会整套固定下来，新版本整套替换。
- 还没做到的：用签名校验网页的每次更新。

在意这一点的话：用命令行客户端 `omnillm connect`（签过名的程序），或者[自己部署网页客户端](self-host.md)。

## 主机和本机

- 主机**不监听任何对外端口**，不需要改路由器或防火墙。它只主动连出去：连模型提供商，连连接服务。
- 本机控制台只开在 `127.0.0.1`。登录要用 `omnillm open` 生成的一次性链接（2 分钟内有效、只能用一次），换成只对本机有效的会话；每个请求还核对 `Host`、来源和自定义请求头。
- 后台服务只属于当前用户，不需要也不接受 sudo。数据目录权限是 0700，文件 0600。
- 主机不保存对话内容，审计记录只记元数据（谁、什么时候、哪个模型、用量）。例外：用 Claude 或 ChatGPT 订阅聊天时，为了下一句不用把整段对话重发一遍，Claude Code 和 Codex 会把这段对话留在主机上它们自己的会话文件里（和你自己用它们时的历史一样，只有你的账户能读）。一天没用、这台设备被移除、或你在控制台移除这个订阅时就删掉；不经过连接服务，也不会到别的设备。

## 发布、安装和更新

- 发布包由 GitHub Actions 从打了标签的代码构建，附软件物料清单（SBOM）；校验和文件用 [cosign](https://github.com/sigstore/cosign) 免密钥签名，签名绑定本仓库的发布流程。
- 安装脚本的下载地址写死在脚本里，不能用环境变量改；它先核对 SHA-256，装了 cosign 的还会核对签名，对不上就停。
- 更新走的是同一个安装脚本：主机自己更新、`omnillm update`、菜单栏里点更新，都是下载官方脚本、按同样的规则核对后重新安装，没有另一条下载路径。开发时自己编译的版本只提示、从不自己替换。
- 新版本装上后启动不起来，安装程序会换回原来的程序文件（`~/.local/bin/omnillm.prev`），以后自动更新跳过这一版。
- CI 运行测试（含竞态检测）、`go vet`、`staticcheck`、`govulncheck`。

## 出了事怎么办

| 情况 | 做什么 |
|---|---|
| 手机或电脑丢了 | 在主机控制台的「设备」里点「移除」，立即生效 |
| 怀疑某个 API Key 泄露 | 到提供商后台作废它，再在控制台换上新的。OmniLLM 删掉 Key 只是从本机删除，Key 本身在提供商那里仍然有效 |
| 主机丢了或被入侵 | 到各提供商后台作废 API Key，在官方程序里退出订阅登录（或在提供商网站上登出所有会话）；然后在新电脑上重新安装、重新配对设备 |
| 收到来历不明的配对链接 | 不要点「添加」。正常情况下，配对链接只来自你自己主机屏幕上的二维码 |

## 更安全的用法

- **自己部署连接服务**（见[自己部署连接服务](self-host.md)）：连接服务能看到的 IP 和连接时间等元数据，就只留在你自己的服务器上。
- **用命令行客户端**代替网页客户端，避开“第一次加载网页要信任托管方”的问题。
- 在控制台里给每台设备只开它需要的模型，把每天额度调低。
- 装 cosign，让安装脚本也核对签名。

## 和别的做法比

想在每台设备上都用自己的订阅或 Key，常见的做法各有问题：

| 常见做法 | 问题 |
|---|---|
| 每台设备各登录一次 | 麻烦；服务器、公用电脑上不想留登录；同一个账号在多处、多个 IP 同时用，容易被判成账号共享而受限，甚至封号 |
| 把 API Key 复制到每台设备 | Key 散在各处，丢一台设备就得换 Key；脚本、配置文件、命令历史里都可能留下 Key |
| 自建一个公网 API 网关 | 要服务器、域名、证书；网关对公网开放，被扫到就会被盗刷；网关能看到你所有的对话 |
| 内网穿透或组网连回家里的电脑 | 要改路由器或装组网软件；每台设备都要装、要登录 |

OmniLLM 让账号只留在主机上，所有请求从这一个出口发出、统一限速；主机不开对外端口，中间的连接服务只转发密文。
