## v0.2.0-alpha.65（2026-10-26）

- 手机网页：新的欢迎和配对页面，有语言切换、跟随深色模式，每种设备只做一件事（电脑粘贴链接就开始配对，手机点一下扫码）。iPhone、iPad 先添加到主屏幕，主屏幕上的应用用同一个码配对一次；在微信等应用里打开的先换到浏览器；配对过程只用一行显示（连接中、6 位数、已连上、失败）；不是 relay.ixxzh.com 的中转会标出提醒。
- 所有模型都被排除出 Auto 时，列表里不再显示 Auto（选了只会失败）。程序要 Auto、而能用的只有只能手动对话的模型时，提示说的是这个原因，不再说成“没登录或到上限”。Auto 每个模型只报一次名字：模型自己报的名字不会在回答中途再来一次，不会把你起的名字改掉，也不会被当成换了模型。
- GitHub 限制这台电脑所在网络地址的查询次数时（不登录每小时 60 次，同一个网络里几台电脑很快就到），更新和网页核对不再停下：改读 GitHub 的发布订阅。两边都被拒时，`omnillm update` 会说是 GitHub 的限制、过一会儿再试，不再说成网络不通。
- 手机网页：“对话只存在这台设备上”的说明写上 Gemini；不保存对话的浏览器只在第一次打开对话时提醒一次。
- 控制台：订阅接入了但来源被关掉时写“来源已关闭”，不再写“已接入”。
- 命令行：`connect pair --no-limit`；已经配对的设备运行 `connect pair` 先说已配对；`hub provider add gemini`（google、antigravity、agy）指向 `omnillm login gemini`，`hub provider off gemini` 能用；`uninstall --purge` 也删掉 Gemini 的登录；设备上只有安装启动的主机能 `hub run`；被移除的设备 `status` 退出码 1 并说先 `connect forget`；`connect chat --model` 写错时给出能运行的命令。
- 手机网页：不能保存配对的浏览器（无痕窗口）里再开一个标签页，原来那页回来时接着用，不再卡住。
- 控制台：来源被关掉的订阅不再在“来源已关闭”下面写“可以用了”。
- 命令行：`status` 和 `omnillm` 菜单列出 Gemini 订阅（`omnillm login gemini`）；只当设备用的电脑上 `omnillm connect` 和 `-h` 显示设备的命令；`hub region confirm` 先确认主机在运行；`hub pair` 不接受 `--budget-usd` 和 `--no-limit` 同时写，给 AI 助手的命令保留选项；`hub app add` 在本机接口没打开时直说；`hub provider off|on` 认 `google`、`agy`；终端里的模型名和 ID 去掉控制字符；帮助里 `login` 一行不再挤在一起。
- 手机网页：回答出字时顶上的模型名不再消失；用 Auto 时，主机一说选了哪个模型就显示出来。
- 命令行：Auto 换了模型时再说一次“(Auto · 模型)”；`omnillm hub region` 给出用法；从脚本运行 `connect models` 时，必要时把 Auto 标成只能手动对话。
- 手机网页：不能保存配对的浏览器只在配对前提醒一次；电脑上配对时连接断了，说换一个链接再粘贴，不再说扫二维码。
- 命令行：hub 子命令后面写 `-h`、`--help` 显示帮助；`hub audit` 多写了字会说；远程连接关着时 `status` 说清怎么才能加设备；`help --all` 里 `hub model set` 写上 Auto 可选；清理 Gemini 记录的 sqlite3 也先查是谁的。
- 手机网页：配对成功后马上打开的另一个配对链接不再被对话盖住。主机每天核对网页时也先整理地址（OMNILLM_WEB_APP 以 index.html 结尾时以前从不核对）。本机接口或 `--listen` 地址写错时说清端口范围。
- 手机网页：同一个配对链接点两次只处理一次；配对时等着的另一个链接在对话打开后再处理。`verify web` 认得从手机地址栏复制来的地址；OMNILLM_API 的端口必须在 1–65535。
- `verify web`：判断 cosign 连不上 Sigstore 时只看它自己的话，不看它引用的证书（签名人可以给自己起名叫“tuf”）；地址上没有网页时说检查地址。
- 手机网页：配对链接留在地址栏直到读完保存的配对；正在回答或配对时打开的链接等结束后再处理。
- 命令行和控制台：`install` 遇到写错的 OMNILLM_API 会停下；主机发来的命令换成这个终端能运行的写法；主机日志和控制台“应用”页说清怎么打开被设置关掉的远程连接或本机接口。
- `verify web`：签名核对用核对过清单的同一份 checksums.txt；装了 cosign 却没有签名文件算签名不对，cosign 连不上 Sigstore 算没能核对；发布的文件清单和校验和对不上时单独说。`hub app add` 给出打开本机接口的命令，地址不在本机时直说。
- 手机网页：换语言后不再重复提醒存不下配对；应用内打开的坏链接从地址栏去掉；读保存的配对时来的配对链接会等它读完。
- 手机网页：iPhone 上在微信等应用里点“仍在这里用”后不再接着要求放到主屏幕；已配对的设备从关着的页面打开坏掉的配对链接，打开完整的对话；换语言后已过的关不用再过。
- 命令行：`verify web` 只在 cosign 确实不认签名时警告，下载失败算没能核对；清单不在发布的校验和里时警告；没有构建号的网页说不是发布构建的；地址要以 http(s):// 开头；`hub app add` 说清本机接口是被设置关掉还是端口被占。
- 命令行：`verify web` 出错时用你的语言说清原因；远程连接关着时 `status` 和配对给出打开它的命令（重新安装会沿用 off）；Auto 能选的都只能手动对话时也标成只能手动对话，脚本默认用能答它的模型。
- 安装和更新：找预发布版时先用主机找到的版本，再问 GitHub 接口，接口限流时读发布订阅，无人值守的更新不再因此失败。
- 手机网页：配对前的几道关各自记住；iPhone 无痕标签页在配对前就说存不下配对，应用内打开的页面不再说两次；已配对的设备打开坏掉的配对链接时留在对话里。
- 命令行：所有模型都只能手动对话时，Auto 不再是脚本、管道的默认，本机接口也不再只给程序一个 Auto；`connect chat`、`connect ask` 说出 Auto 选的模型；`omnillm connect -h`、`omnillm hub -h` 显示帮助；`hub models` 多一列“Auto 可选”，`hub model set` 支持 `--auto true|false`；远程连接关着时 `hub pair` 先说加不了设备；地区没变时 `hub region confirm` 说不用确认。
- 安全：Gemini 订阅的 agy 设置只保留 `trustedWorkspaces`、`showTips`；设置和钩子写临时文件再改名，内容没变不写；删除对话时也删掉它的标题、锁和摘要记录，以前版本留下的顺带清掉。

## v0.2.0-alpha.60（2026-10-26）

- 手机网页：主机没给这台设备任何模型时，直接这样说，不再报一句错误、还像是连不上。
- 手机网页：“连不上你的 Mac”到处是同一句；订阅登录失效时，提示和报错用同一个名字、同一个修法；用量上限不是今天恢复时写上星期几；还没出字就停止不再显示红色错误；载入失败只说一句话。
- 控制台：向导最后一步随时能点“完成”；移除模型来源时说清模型会从所有设备消失、保存的 API Key 会删掉；已接入但登录失效的订阅卡片上显示“登录”；地区暂停、手机网页核对不一致时，窄窗口里也写出原因。
- 命令行：`omnillm uninstall -h`、`install -h` 只显示帮助，不再真的卸载或重装，写错的选项会停下；主机没在运行时，hub 命令用你的语言说“OmniLLM 没有运行”；命令写错时只给原因和“全部命令在哪看”；`connect ask` 把 `--model` 写在问题后面会提示；还没出字就 Ctrl-C 只是停下。
- 命令行：`hub provider add` 先认种类（订阅要用 `omnillm login`）、先确认 OmniLLM 在运行再要 Key；`hub app add` 给令牌时带上接口地址；`hub models` 标出已关闭的来源；主机没运行时 `status --json` 退出码为 1；只当设备用的机器卸载时指向 `connect forget`。
- 控制台：登录失效的订阅卡片直接给“登录”，不再说已接入；从仪表盘“接入模型”接好后回到仪表盘，已接入的 Ollama 不再推荐；向导里切换语言保留已经打的字；更新时打开控制台会自己重试；地区暂停时菜单栏不再说“在线”。
- 手机网页：重新载入（换语言、新版本）后回到原来那个对话；正在打字或带着图片时不会自动重载；配对时连不上电脑会提示换一个新的二维码；Android 有自己的“添加到主屏幕”说明。
- 命令行：订阅可以写成 `claude`、`chatgpt`，`hub providers` 显示 ID；移除带 Key 的来源会说 Key 也删了；`openai-compatible` 先要名字和地址再要 Key；在设备上或没装 OmniLLM 时运行 hub 命令会直说；`/image` 认 `~/` 和拖进来的路径；`--model` 写错立即提示；`status` 检查参数，设备上会报告是否已配对。
- 命令行：主机拒绝一条命令时（名字不对、Key 不能用、配对过期），显示它自己的那句话，不再是“出了点问题”。`hub audit` 给脚本用时仍输出 JSON。没配对的设备在 `status`（退出码 1）、主机命令和 `connect forget` 里都直说。
- 控制台：“模型”里登录失效的订阅旁边直接有“登录”按钮；控制台和本机接口的提示只在 Mac 上说“你的 Mac”。
- 控制台：重新登录后，登录失效的订阅半分钟左右就恢复，不用再等最多 5 分钟；不是 Mac 的主机上，“登录”按钮也能用。
- HOME 不是你自己的家目录时（测试、沙盒），`omnillm install` 和 `uninstall` 不再去动你真正的后台服务。
- 手机网页：载入失败时说出原因（浏览器禁止网站保存数据，或没联网），不再一律说“程序意外停止”。
- 命令行：设备没有能用的模型时直说，并指向怎么看它能用哪些模型，不再说成“Mac 上没有模型”；`hub device set` 改完后设备一个模型都用不了时会提醒。
- 后台服务在运行时再运行 `omnillm hub run`，会说 OmniLLM 已经在运行（并给出日志位置），不再启动第二个和它抢的主机。
- 手机网页：已配对的手机打开新的配对链接又退回时，回到能用的对话。
- 命令行：被主机移除的设备会提示先 `connect forget` 再 `connect pair`；在主机自己身上运行 `connect` 命令时说这台就是主机。
- 没有服务管理时（WSL、容器），安装或更新会先停掉正在运行的主机再启动新的，更新才真正生效。
- 模型来源都关掉时 `status` 会直说；配对的设备用不了任何模型时不再说“直接对话就行”；Ollama 没运行时 `hub provider add ollama` 会直说。
- 手机网页：发出的问题马上存下，手机在后台回收页面也不会丢；保存不了配对的浏览器不再自己重载（那样会丢掉配对）。
- 控制台：再打开一个控制台标签页（菜单栏每次都会开一个）不会再把已经打开的那个踢下线。
- 手机网页：正在打的字在手机回收后台页面时也会保留；离线时没载入成功的页面，联网后会自己重新载入。
- 命令行：没有服务管理时，更新也能换掉旧版本起的主机，换不上会直说；`hub provider add ollama` 的地址可以不写 `/v1`；对话中途模型被关掉会换一个能用的；本机或局域网的 openai-compatible 服务在要 Key 之前就说清不支持的原因。
- 命令行：`hub provider add ollama --base-url http://localhost:11434` 能用了（以前只试 localhost 的第一个地址）；本机 http 的 openai-compatible 服务在要 Key 前就会拒绝；Ollama 地址用不了时说明原因；设备上的 `omnillm help` 列出设备的命令。
- 手机网页：有新版本时不会在配对过程中重载页面；电脑不再应答时说“连不上”，不再说“出了点问题”。
- 命令行：`omnillm help` 列出 `omnillm login gemini`。
- 命令行：来源的名字和地址在要 Key 之前就检查；地址没人应答时提示检查地址（不再说“稍后再试”）；远程连接关着时配对会直说；只用 `connect pair` 配对过的电脑也算设备。
- 手机网页：开着两个标签页时，重载后正在用的那页不会再存不了对话；切回一个标签页时保留在那里打的字。
- 控制台：Ollama 一个模型都没有时，“重新检查”也会说该 pull 哪个，提示停留得够读完。
- 安全：终端里显示的模型回复去掉控制字符，回复不能借转义序列改剪贴板或伪造提示。
- 安全：设备上 `uninstall --purge` 会删掉配对；属于别的用户的控制通道单独警告。
- 安全：设备发来的消息前面不管是什么样的空白（Unicode 空格、零宽字符），以“/”开头的都只当普通文字。

## v0.2.0-alpha.3（2026-10-20）

第三轮安全审查和公网测试后的修复：

- 图片：除了格式和大小，还按图片头里的尺寸拦下“几 KB 却声称几十亿像素”的图片（单边 ≤ 8192，总共 ≤ 约 4000 万像素），免得主机上的 Claude Code / Codex 解码时吃光内存。

- 网页客户端：页面、脚本和 Service Worker 带同一个构建号；服务器切换版本时恰好打开、拿到新旧混合的页面，会自动清缓存重新载入一次，不会把混合版本缓存下来。
- 服务器部署：连接服务用自己的无登录账号运行（systemd 加固），网页文件归 root、只读，连接服务被攻破也改不了手机加载的网页；打包没有 cosign 就停下；服务器上安装前再核对一遍签名的校验和；网页目录不跟随符号链接；如果有日志格式会记录浏览器信箱口令所在的请求头，安装就停下。
- 手机断网时马上提示“这台设备没有联网”，刚输入的内容留着，联网后自动重新连上；连上主机前就点了发送的消息，会等模型列表加载好再发出（公网上列表比聊天界面晚到一点）。
- 连接服务对 IPv6 按 /64 计猜口令次数。
- Codex 附图片改成单个参数，不会把读提示词的 `-` 当成图片。

## v0.2.0-alpha.1（2026-10-19）

Mac 上登录好的 Claude 或 ChatGPT 订阅，手机、平板、Linux 服务器都能用；除了 Mac，别处尽量不装东西。

- 订阅：中心节点直接用已登录的 Claude Code 和 Codex（官方程序），当纯文本模型跑：不开工具、不读主人的设置和说明文件、不留会话；Codex 在中心节点自己的目录里跑，只链接主人的登录文件。装好、启动、`omnillm status` 或打开控制台时自动接上。
- 防封号：订阅只给人用（代码里写死，主人也关不掉）；一次一个、每分钟 12 次、每台设备每小时 60 次；订阅用量到顶就按官方给的恢复时间暂停；每个新版本的官方程序先过“能不能用工具”的检查，过不了就不用。
- 手机和平板：扫控制台上的二维码直接打开网页客户端（不装 App），在网页里配对和对话；加密在网页里用和命令行同一份代码（WebAssembly）完成，配对状态和对话加密存在浏览器里。
- Linux 服务器：`install.sh --device` 只放一个程序、不装服务，粘贴配对文字就能用；`omnillm connect chat` 在终端里多轮对话；脚本（没有终端）用不了订阅。
- 被移除的设备会被明确告知“已被移除”，不再一直显示“连不上主机”。
- 公共连接服务 `wss://relay.ixxzh.com` 和网页客户端 `https://omni.ixxzh.com`（放在 ixxzh.com 的服务器上，步骤见 docs/relay-deploy.md）：中心节点默认连它；网页客户端随发布签名，不再用 GitHub Pages。
- 请求节奏：订阅额度暂时用完时，20 秒内能轮到的就等一下再发，不再报错。

## v0.1.0-alpha.2（2026-10-18）

两台机器（Linux 服务器做中心节点、Mac 做中心节点）各跑多轮完整流程后修的问题：

- 半途放弃的配对不再占名额：命令行退出、控制台重开“添加设备”或关掉页面、SDK 的 ctx 结束，配对都立即作废。以前 8 次放弃之后 5 分钟内配不了新设备。
- relay 刚重启时发起配对会等它重连（最多 15 秒），设备连信箱最多重试 20 秒；连不上 relay 时提示“连不上”，不再误报“配对文字过期”。
- relay 断开后中心节点几秒内重连（间隔封顶 10 秒）；连上又马上断的才继续拉长间隔。
- 控制台默认端口被别的程序占用时换下一个空闲端口，登录链接跟着走；只有嵌入模型的 Ollama 不自动接入；没有屏幕的机器提示在终端里输入密钥；Linux 服务也写 hub.log；设备本机接口令牌错误时提示清楚；发布附带 Sigstore bundle。
