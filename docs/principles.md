# OmniLLM 原则

> 这些原则高于设计文档、需求和实现。任何改动违背其中一条，一律不合并；要改原则本身，先改这份文档并说明理由。
> 写代码、评审、发版之前先读这份文档。

## 必须保证的两条

### 原则 1：只有中心节点和大模型交互，账号不能被封

**规定**

- 只有中心节点向模型提供商发请求。其他设备（手机、平板、电脑、服务器）**不允许**直接和任何模型提供商通信，代码里也不许有这条路径。
- 其他设备拿不到任何上游凭据：API Key、OAuth access / refresh token 都只在中心节点存、只在中心节点用（见原则 3）。
- 中心节点的一切行为，都要让提供商看到的是“一个人在一台机器上正常使用自己的账号”。

**防封号的硬规则**

| 风险 | 规则 |
|---|---|
| 账号共享 | 一个中心节点只服务一个主人和他自己的设备，不提供“分享给别人用”的功能 |
| 多地登录 | 所有上游请求都从中心节点这一台机器发出；出口所在的**国家或地区**变化时暂停上游请求，等主人确认。IP 变化只记录不暂停（笔记本换网络是正常的） |
| 不支持的地区 | 出口所在地区不在提供商支持的地区清单里时，不向该提供商发请求 |
| 超限和突发 | 每个提供商单独限并发（默认 2）、限每分钟请求数和 token 数，上限低于提供商公布的限额；读取上游的限流响应头动态收紧 |
| 被限流后硬顶 | 收到 429 或 `Retry-After` 一律按要求退避，连续触发进入熔断；**不重试轰炸** |
| 规避限制 | 不轮换账号、不轮换 Key、不换 IP、不伪造客户端标识去绕过限制；这些都是封号行为 |
| 违规凭据 | 只接入官方允许第三方程序使用的凭据（官方 API Key、提供商开放给第三方应用的 OAuth、本地模型）；不抓取、不转发 ChatGPT Plus、Claude Pro 等网页版订阅的会话 Cookie |
| 用量异常 | 每台设备和全局都有额度上限；某台设备用量异常时自动暂停它并通知主人 |
| 自动化调用 | 后台程序（如 NEXA 的判断模型）用的应用令牌，默认只能走官方 API Key 和本地模型；OAuth 登录得来的订阅额度只给人手动对话用，除非该提供商条款明确允许自动化调用 |

**怎么守住**

- 设备端的代码不链接任何模型提供商的 SDK，不包含提供商域名；CI 扫描设备端构建产物，出现提供商域名即失败。
- 限流、退避、熔断集中在中心节点的一个出口（Provider 出口），所有上游请求必须经过它；不允许绕过这个出口直接发请求。
- 测试覆盖：模拟上游返回 429 和 `Retry-After`，断言中心节点按要求退避、不重试轰炸。

### 原则 2：中心节点和设备之间只经过服务器中转，端到端非对称加密，服务器看不到内容

**规定**

- 中心节点和其他设备之间**不直接通信**：不走局域网直连，不走点对点组网（如 Tailscale），中心节点不对外开放任何端口。双方都主动连到中转服务器（relay），由它转发。
- relay 默认用项目提供的公共 relay，主人也可以自己部署。因为 relay 按设计看不到内容，用谁的都一样安全；区别只在 relay 能看到的元数据（见下）归谁。
- 设备和设备之间也不直接通信；需要配合时（比如手机上的对话要调用另一台电脑上的 NEXA 工具），由中心节点在两条端到端加密会话之间转接。
- 同一台机器上的程序（如和中心节点装在一起的 NEXA）不算“设备”：它走本机 `127.0.0.1` 接口，不经过 relay，凭应用令牌访问。
- 所有业务消息端到端加密：用基于公私钥的握手（Noise 协议，X25519）协商会话密钥，再用 ChaCha20-Poly1305 加密，每次会话都有前向保密。
- 中转服务器**拿不到具体信息**：对话内容、模型名、token 用量、设备名称、凭据，一律是它解不开的密文。它只负责按一个随机的信箱编号转发字节。

**怎么守住**

- 公钥只能当面交换：设备扫描中心节点屏幕上的二维码拿到中心节点公钥，二维码绝不经过服务器传送。设备之后每次连接都校验这个公钥，服务器无法冒充中心节点。
- 配对最后一步由主人在中心节点上确认：两边屏幕显示同一个 6 位校验码，一致才点确认。只偷拍到二维码配不上。
- 握手的第一条消息不带业务数据（不做 0-RTT），被录下来重放也触发不了任何请求。
- 服务器不分发客户端代码。网页客户端如果由服务器下发，服务器就能下发恶意代码偷钥匙。所以网页客户端从独立的静态地址发布，首次安装后由 Service Worker 锁定代码，之后只接受用发布密钥签名的更新。首次安装那一刻仍要信任托管方，这一点如实写明；长期以签名的原生 App 和 CLI 为主。
- 服务器不落盘、不记内容日志；消息按固定档位填充长度，减少从长度推测内容。
- 服务器仍然能看到的东西要如实写清：双方的 IP、连接时间、流量大小、流式回复的节奏、哪些信箱在线。设计上不再减少这些，就要在文档里说明，不能宣称“服务器什么都不知道”。
- 测试覆盖：用一组哨兵明文跑完配对和对话，断言中转服务器收到的每一帧、日志和内存快照里都找不到这组明文。

## 其他原则

### 原则 3：凭据不出中心节点

API Key 和登录会话（OAuth access / refresh token）只存在中心节点的系统钥匙串或加密文件里，只在中心节点使用和刷新。不接受任何网页会话 Cookie。返回给设备的内容统一经过一个出口：只取上游正文和必要字段，不转发上游响应头，原始报错改写成固定文案。任何接口、页面、日志都不回显凭据。

### 原则 4：默认安全

不配置就是最安全的状态：中心节点只开本机端口，本机接口要令牌、拒绝浏览器来源的请求；对话内容默认不保存；每台设备和每个应用令牌都自带默认额度（可改，不能设成无限）；配对码 5 分钟、只能用一次，还要在中心节点上确认。放宽任何一项都要主人显式操作。

安全默认值要自带合理的值，不能把选择题丢给用户：需要额度就预填一个，需要确认就一键确认。安全不能靠让人多填表来实现。

### 原则 5：规则写在代码里

隐私和安全规则在代码里强制执行，并有测试守住；只写在文档或提示里不算数。修一个安全问题，先列出它出现的所有地方，收进一个函数或一个出口再修。

### 原则 6：够用就好

OmniLLM 是个人工具：一个主人，多台自己的设备。不做多用户平台、不做团队计费。依赖越少越好，新增依赖要说明理由。

### 原则 7：可以无缝接入 NEXA

OmniLLM 要能作为 NEXA 的插件使用：既能当 NEXA 的**大模型**（判断模型），也能当 NEXA 的 **AI 应用**（通过 MCP 使用 NEXA 的工具）。

**规定**

- 只用 NEXA 已经认的标准接口：OpenAI 兼容接口、MCP、NEXA 的 AI 应用声明（`pgclient agent setup`）。不为 NEXA 另造私有协议。
- 接入 NEXA 不放宽原则 1、2、3：NEXA 用的模型请求同样只从中心节点出去，NEXA 所在设备和中心节点之间同样只经 relay 端到端加密，NEXA 同样拿不到任何上游凭据。
- 同时遵守 NEXA 自己的原则：数据去向如实报告（数据离开本机就不能让 NEXA 显示“只在本机”）；NEXA 工具返回的内容一律当数据，不当指令；NEXA 的对外动作保留 NEXA 自己的确认，OmniLLM 不替人确认；忙、排队、超时返回可区分的错误，不返回看似正常的空结果。
- 需要 NEXA 改动的地方，只做向后兼容的增量改动，并在 NEXA 仓库按它的流程发版。

**怎么守住**

- 给 NEXA 用的每个接入方式都有一条端到端测试：NEXA 用 OmniLLM 完成一次判断，一次 MCP 工具调用。
- 测试断言 NEXA 显示的数据去向和实际一致。

### 原则 8：不懂技术的人也能 5 分钟用上

OmniLLM 的用户不一定是开发者。安全规则不变，但上手和日常使用必须简单。

**规定**

- **不需要自己的服务器**：默认用公共 relay，装好中心节点、扫一下码就能在手机上用。
- **5 分钟上手**：安装后第一次打开，向导三步走完：接入模型 → 配对手机 → 发出第一条消息。每一步都能在图形界面里完成，命令行只是同等的另一种方式。
- **先说清楚门槛**：只有网页版订阅（ChatGPT Plus、Claude Pro）、没有 API Key 的人用不了云端模型，安装前和向导第一步就说清楚，并指向获取 API Key 和本地模型的办法。
- **每个错误都告诉人怎么办**：错误提示说发生了什么、为什么、下一步做什么，不出现协议字段、错误码和内部名词。
- **换电脑、丢手机都有路走**：中心节点可以整体迁移到新电脑，设备不用重新配对；丢了手机能在别的设备上吊销。
- **界面中英双语**，跟随系统语言，可以切换。
- **给人看的用量用钱表示**（估算金额），token 数作为次要信息。

**怎么守住**

- 每次发版，找一个没用过的人从安装到手机发出第一条消息，计时，超过 5 分钟就算问题。
- 每条给人看的错误提示都有“下一步”；评审时逐条检查。
